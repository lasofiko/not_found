# Контракт Backend API v1

Базовый путь по умолчанию: `/api/v1`. JSON, UTF-8. Реализованные маршруты видны в `/docs` и `/openapi.json`. Никаких транспортных значений текущие инфраструктурные маршруты не возвращают.

## Реализовано

### `GET /health`

HTTP 200: `{"status":"ok","service":"baltic-balance-backend","api_version":"v1"}`. Проверяет только процесс API; доступность данных и модели определяется по `/status`.

### `GET /config`

HTTP 200. `supported` описывает задуманные варианты, не наличие наблюдений; `available` содержит только действующие аналитические варианты. Пустой массив означает, что функция пока недоступна.

```json
{
  "supported": {
    "directions": ["inbound", "outbound"],
    "transport_modes": ["sea", "rail", "road", "air", "all"],
    "mass_units": ["tonnes", "thousand_tonnes"],
    "granularities": ["month", "quarter", "year"],
    "horizon": {"working_target_year": 2030, "conditional_extension_year": 2035}
  },
  "available": {
    "history_granularities": [],
    "forecast_granularities": [],
    "forecast_target_years": []
  }
}
```

`inbound` — в область, `outbound` — из области. `all` — выбор всех *доступных* видов, не отдельный вид в таблице наблюдений. `rail` — код выбора в интерфейсе; в нормализованных наблюдениях принят `rail_land`. Перед реализацией истории требуется утвердить преобразование `rail` ↔ `rail_land`. Месячный шаг предпочтителен, но доступность зависит от проверенных рядов. 2035 — условное расширение, не обещание модели. `thousand_tonnes` — формат отображения массы.

### `GET /status`

HTTP 200:

```json
{
  "components": {
    "backend": "ready",
    "data": "not_connected",
    "ml": "not_connected",
    "scenarios": "not_connected"
  },
  "capabilities": {
    "historical_data": false,
    "forecast": false,
    "scenario_analysis": false
  }
}
```

Состояния компонентов: `ready`, `not_connected`, `unavailable`. `ready` означает пригодность компонента для заявленной функции; `unavailable` зарезервировано для отказа ранее подключённого компонента. Сейчас состояния заданы по фактическому составу приложения. При будущей интеграции они должны вычисляться из проверяемой готовности модуля и данных. Существующий расчёт чувствительности `/scenarios/capacity` не делает полноценный сценарный модуль готовым.

### Сохранённый `POST /scenarios/capacity`

Принимает `demand_tonnes`, `capacity_tonnes`, `capacity_delta_tonnes` (числа ≥ 0, одна временная база), `period` (`YYYY` или `YYYY-MM`), `assumption_source` (непустая строка). Возвращает `period`, `unit: tonnes`, `status: scenario`, `assumption_source`, `baseline_shortfall_tonnes`, `scenario_capacity_tonnes`, `scenario_shortfall_tonnes`, `shortfall_reduction_tonnes`, `warning`. Это арифметическая чувствительность по пользовательскому вводу, не прогноз или подтверждённый эффект. Маршрут оставлен для действующего Frontend.

## Ошибки

Формат: `{"error":{"code":"VALIDATION_ERROR","message":"Некорректные параметры запроса","details":[{"field":"body.period","message":"..."}]}}`. `details` — массив, пустой если дополнительной информации нет. HTTP 422 / `VALIDATION_ERROR` для ошибочного запроса; 404 / `NOT_FOUND` для отсутствующего маршрута; 405 / `METHOD_NOT_ALLOWED` для неподдерживаемого метода; 500 / `INTERNAL_ERROR` для внутренней ошибки. Stack trace в ответе отсутствует, внутренняя ошибка записывается в журнал сервера. Некорректные переменные окружения прерывают запуск через валидацию настроек.

## Предварительные будущие маршруты — пока не реализованы

Все поля этого раздела требуют согласования с владельцами данных, ML и сценариев. Маршруты не включены в OpenAPI.

| Маршрут | Предварительный запрос | Предварительный ответ |
|---|---|---|
| `GET /history` | `direction`, `mode`, `start_period`, `end_period`, `granularity`, `cargo_group`, `unit` | `status: observed/estimated`, временной ряд с периодом и единицей, география/OD, `source_id`, версия данных, покрытие, предупреждения. Оценки отделяются от наблюдений. |
| `POST /forecast` | `target_year`, `direction`, `mode`, `cargo_group`, `granularity`, `unit`; сценарные параметры только после согласования | `status: forecast`, базовый ряд, период и единица, география/OD, версии данных и модели, происхождение, ограничения, предупреждения; метрики и интервалы при наличии. Сценарный результат маркируется отдельно как `scenario`, а не прогноз. |
| `GET /scenarios` | Без параметров или фильтр по доступности | Карточки утверждённых действий: механизм, участок, дата, параметры и диапазоны, CAPEX/OPEX и источники. |
| `POST /scenarios/compare` | Идентификаторы сценариев и согласованные параметры | Сопоставимые показатели с единицами, периодом, статусом `scenario`, происхождением и предупреждениями. |
| `GET /sources` | Фильтры по периоду, виду и статусу | Паспорт: `source_id`, организация, место/URL, дата, география, показатель, единица, ограничения, SHA-256 и покрытие. |
| `POST /datasets/upload` | Файл и метаданные только после утверждения схемы и правил доступа | Результат валидации, версия данных, ошибки строк, статус приёмки; никаких автоматических трактовок неизвестной географии. |

Data Service впоследствии читает только проверенный нормализованный набор по `docs/contracts.md`, фильтрует и агрегирует без двойного счёта. Forecast Service вызывает готовый модуль ML и возвращает его версии, временную проверку и ограничения. Scenario Service применяет только утверждённые параметры; изменение мощности само по себе не равно росту грузопотока. Calculation Service отвечает за проверяемые единицы и пересчёты. Сейчас этих сервисов нет.

2. **ML Lead (Петя):** сигнатура прогнозного модуля, допустимые направления/виды/частоты/горизонты, версии, базовый и сценарный результат, интервалы, метрики, период backtest, обработка недоступного среза.
3. **Research & Transport Analyst (Рома):** две утверждённые гипотезы, механизм и участок действия, сроки, мощность/время, CAPEX/OPEX, источники диапазонов и методика сравнения; без этого только чувствительность к вводу.
4. **Team Lead:** обязательный интерфейс MVP, целевой горизонт и правила показа ограничений. После согласования обновить `docs/contracts.md` до реализации публичных полей.
