# Сводный комплект: обработка и запуск из репозитория

Использован `not_found-data-bundle-2026-11-10-part1-processed.zip` из корня проекта.
Пользователь явно выбрал обработку без второй части с raw-источниками.
Исходный ZIP сохранён неизменным в `data/raw/team_bundles/<SHA-256[:16]>/package.zip`.
Архивные скрипты не выполняются; код и протокол из ZIP не заменяют репозиторий.

## Исправление ошибки манифеста

Старый манифест связан с прежним кодом, документами и оригиналами. Его хеши
не исправляются вручную. Новый конвейер читает таблицы непосредственно из
проверенного ZIP, заново записывает их CSV с новой `data_version` и создаёт
собственный манифест `provided_processed` под текущий код. Числовые значения,
названия показателей, периоды, OD, статусы, исходные идентификаторы и ячейки
сохраняются. Исходный манифест остаётся в ZIP.

`pipeline.verify` для этой схемы проверяет исходный ZIP, построчное совпадение
значений предоставленных и пересобранных CSV, единицы, ссылки на паспорта,
состав и хеши кода. Прежняя строгая проверка наборов с оригиналами не меняется.
**Уровень проверки: предоставленные таблицы; первичные HTML/PDF/XLS повторно
не проверены.** Старые JSON-отчёты в корне `data/processed/` относятся к исходной
версии и сохраняются как контекст, текущая версия задаётся build_manifest.json.

## Запуск

Из корня проекта с Python 3.11+, сначала установите объявленные зависимости:

```bash
python -m pip install -e ".[data,ml]"
python -m pipeline.team_bundle --from-processed not_found-data-bundle-2026-11-10-part1-processed.zip
python -m pipeline.team_bundle --prepare
python -m pipeline.verify
python -m ml.run --end-year 2030
python -m ml.port_run
python -m ml.port_run --all-targets
```

Первая сборка сохраняет прежние локальные результаты в `previous/` рядом
с неизменным ZIP. Повторение использует те же входы. После изменения кода,
контракта или зависимостей повторите `--from-processed`: прежний манифест
должен отклонять изменения. Проверка воспроизводимости: `python -m pipeline.reproduce`.
Локальный архив передачи: `python -m pipeline.package`; внешней публикации нет.
В архиве передачи исходный processed-ZIP лежит по пути `source_bundle.local_path`
из build_manifest.json. Этот путь можно передать в `--from-processed` вместо
исходного имени в корне. Региональные таблицы восстановятся из этого же ZIP.

## Где результаты

- [Новая сборка](../data/processed/build_manifest.json): версия, SHA-256 входов,
  старое происхождение, текущий код, уровень проверки и выходные файлы.
- [Каталог дополнений](../data/processed/team_bundle/table_catalog.csv): все 16
  предоставленных CSV и пути к очищенным таблицам в `tables/`.
- [Реестр дополнений](../data/processed/team_bundle/source_registry.csv): пути
  производных таблиц, хеши и ссылки публикаций с отдельным статусом доступности.
- [Исследовательские факты](../data/processed/team_bundle/research_facts.csv):
  306 строк из трёх файлов, без превращения в обучающие наблюдения.
- [Флот](../data/processed/team_bundle/ferry_fleet_monthly.csv): 28 строк,
  противоречия сохранены. Количество судов не переводится в тонны.
- [Конфликты](../data/processed/team_bundle/conflicts.csv): 51 предоставленная
  конфликтная строка фактов и одна строка флота. При появлении новых противоречий
  число может вырасти; приоритет источникам автоматически не назначается.
- [Кандидаты для исследования](../data/processed/team_bundle/research_candidates.csv):
  исключены конфликты, report_only, прогнозы и планы; это не обучающая цель.
- [Покрытие протокола](../data/processed/port_protocol/coverage.csv): все пять целей.
  Для каждого ряда отдельно сохранены training_series.csv и vintages.csv с
  источниками, ячейками, формулами и доступностью. Пустые массы не равны нулю.

Код нормализации не объединяет различные единицы и уровни. Числовой скаляр
лежит в `normalized_value`; перевод совместимой массы — в `value_tonnes`.
Исходные `value`, `unit`, статусы и текст сохраняются. Специальные коды и
нескалярные записи не превращаются в числа; случаи перечислены в row_issues.csv.
Широкие таблицы и их длинные представления не считаются независимыми наблюдениями.

Существующие `ml/inputs/` сохранены. Новый набор дополнений имеет свой реестр
и ограничения; объединять его с целью обучения нельзя. Исторические модули
гипотез продолжают использовать свой набор, а новые исследования могут читать
подготовленные таблицы по их явному пути.

## Месячный протокол

Следуем [зафиксированному протоколу](ml-port-evaluation-protocol.md);
исторический раздел «Реализация» в нём описывает состояние до этой доработки.
Фактическая конфигурация — `ml/port_protocol.toml`, изменение правил отклоняется.

Три ряда Калининграда имеют 43 последовательных месяца с июня 2022 до декабря
2025, до начала выбора доступны 24 последовательных месяца при учёте публикаций.
Из предоставленных таблиц не удалось выделить месячный портовый каботаж
Петропавловска-Камчатского и Владивостока. Общерегиональные ряды, портовая
перевалка другого охвата и OD-публикации их не заменяют. В coverage.csv эти цели
отмечены `not_present_in_provided_tables`.

Методы: naive, seasonal_naive, drift, ses. Сложные методы не сравниваются.
Выбор по MAE горизонта 1 месяц: июль 2024 — июнь 2025; проверка: июль — декабрь
2025. Прогнозы на три месяца рекурсивные. Пропуски и сбои явно видны в backtest.csv;
метрика не публикуется при покрытии менее половины окна. Нехватка истории
означает только naive без выбора. Проверка не меняет выбранный метод.

Слепая проверка не выполняется обычной командой. После фиксации метода:

```bash
python -m ml.port_run --target kaliningrad_ferries --blind-check
```

Она открывает только нужные итоги 2026, сравнивает сумму января–августа и
сентябрь с выбранным методом и naive. Повтор того же зафиксированного состояния
читает сохранённый результат; изменение состояния после просмотра отклоняется.
Итоги не участвуют в подборе. Проверка сентябрьской разности сопоставляет
арифметику предоставленных накоплений, не подтверждает их первичный источник.
Статус проверки и пределы независимости указаны в паспорте модели.

Модели и отчёты: `models/port/<target_id>/latest.json`,
`reports/generated/ml-port/<model_version>/`. Основной указатель сохранён как
`models/port/latest.json`. Годовая модель остаётся независимой.

## Приёмка

ИИ подготовил импорт, нормализацию, диагностику, адаптацию моделей и машинные
проверки. Автоматическая проверка подтверждает сохранность, структуру и
арифметику предоставленных таблиц. Человек ещё должен проверить первичные
числа, охват, конфликты и методику; приёмка остаётся `pending`. Материалы SeaNews,
их производные, исходные архивы и модели не коммитятся и не публикуются.
