## Пакет паспорта кандидатной цели

Актуальный контракт передачи — v0.8. Паспорт цели: [target-series-passport.md](target-series-passport.md), качество: [data-quality-report.md](data-quality-report.md), краткие сведения Роме: [roma-data-summary.md](roma-data-summary.md). Эти три документа воспроизводятся сборкой. Общий README проекта не меняется.

Кандидат — 18 годовых значений операций одной линии за 2015–2023, по девять на направление, а не тоннаж всего коридора. Один первичный HTML даёт все 18 строк. Дополнительные 2011–2014 сохранены в оригинале и используются лишь в отдельном исследовании; основной ряд не расширяется молча. `observations.csv` до решения команды не выпускается.

```bash
python3 -m pipeline.build --available-only
python3 -m pipeline.verify
python3 -m pipeline.input_check data/processed/candidate_observations.csv --observed-only
python3 -m pipeline.package --output reports/generated/data-handoff.zip
```

В `data/processed/target-source-check.csv` — построчная автоматическая сверка с конкретными HTML-ячейками; в `terminal-component-check.csv` — отдельная проверка состава опубликованного итога терминала, без принятия прочерка за ноль. `coverage.csv` показывает диапазоны извлечённых рядов, `corridor-coverage.csv` — в том числе отсутствующие ячейки 2015–2026 × два направления × четыре вида. Наличие строки `sea` означает лишь покрытие одной линии.

`data/human-review-log.csv` пока содержит только заголовок. Реальный человек заполняет имя, реальную дату, источник, SHA-256, место и результат после сверки. ИИ не подписывает приёмку за Мишу/Рому. Сборка проверяет запись, включает её хеш в версию и не перезаписывает журнал. Запись человеческого решения о методике и принятии цели ведётся отдельно командой: сгенерированный паспорт всегда сохраняет `pending`.

Свои данные: [шаблон CSV](../data/examples/observations-template.csv), [правила заполнения](data-input-guide.md). Старый `pipeline.validate` остаётся для базового контракта; `pipeline.input_check` требует также происхождение и проверяет только фактически используемые источники, что подходит частичному комплекту.

Получателю: сверить SHA-256 архива с файлом `data-handoff.zip.sha256`, распаковать в новую папку, перейти в неё и выполнить без сети:

```bash
sha256sum -c /путь/к/data-handoff.zip.sha256
python3 -m pipeline.verify
python3 -m pipeline.reproduce
python3 -m pipeline.input_check data/processed/candidate_observations.csv --observed-only
```

Команду `sha256sum` запускайте из папки, содержащей ZIP и sidecar: имя файла в sidecar относительно этой папки. `pipeline.reproduce` сначала проверяет переданный комплект, пересобирает в записанном режиме и сравнивает **все** хеши выходов и манифест. Python 3.11+, стандартная библиотека; для старого XLS используется включённый проверенный wheel xlrd. Оригиналы, пути пользователя и интернет не требуются вне пакета. Внутри `data/raw/` находятся сохранённые оригиналы, а не ссылки на внешнюю папку.

Автоматическая пересборка распакованной копии не является независимой приёмкой другим участником. Получатель после своей проверки фиксирует имя, дату и результат отдельно. Архив остаётся внутренним: оригинал транзитного XLS содержит реквизиты участников, а очищенный набор их не содержит.

Базовые HTML/XLSX читаются на Python 3.11+ стандартной библиотекой; старый XLS — `xlrd==2.0.2`, дополнительные PDF — PyMuPDF, OSM — osmium. Для полного нового комплекта сначала установите зафиксированные зависимости, как описано выше. Обучение модели и запуск API для подготовки данных не нужны. Все команды выполняются из корня проекта или распакованного архива.

## Уже подготовленный результат

### Файлы в data/incoming и частичный комплект

После установки `pip install -e ".[data,notebooks]"`:

```bash
python -m pipeline.acquire --local-dir data/incoming
python -m pipeline.build --available-only
python -m pipeline.verify
python -m pipeline.package
```

Импорт известных файлов из указанной папки, включая два ZIP и Unicode-имена, работает без сети. Пустая/неизвестная папка отклоняется. Внутренние манифесты ZIP проверяются до регистрации вложений; одинаковые байты не размножаются. `acquisition_locations` связывает вложения с архивами. Повторный импорт восстанавливает отсутствующие оригиналы, сохраняя паспорта. Предоставленные Excel/ZIP перенесены из корня в `data/incoming/` с исходными именами; импорт их не удаляет. Папка исключена из Git.

`--available-only` разрешает отсутствие оригиналов, но не порчу. Манифест фиксирует `build_scope`, `unavailable_source_ids` и входы. Последний отсутствующий снимок не заменяется старым. `verify` проверяет состав этого комплекта; `package` включает его входы. Получатель повторяет `build --available-only`, если таков режим переданного комплекта. Для XLS нужен установленный xlrd либо включённый проверенный wheel; зависимости ноутбука устанавливаются до офлайн-запуска.

Без первичной страницы направленного ряда `candidate_observations.csv` содержит заголовок: `--require-observations` правильно отклонит его. Копия годового CSV из ZIP остаётся в `supplemental_freight.csv` с `provided_derivative` и `review_status: pending`. Последующие разделы описывают также полный комплект: не предполагайте наличие всех его оригиналов в частичной передаче.

Новые таблицы: `regional_indicators.csv`, `regional_freight.csv`, `supplemental_freight.csv`, `port_cabotage_cumulative.csv`, `port_cabotage_monthly.csv`, `border_crossings.csv`, `freight_coverage.csv`, `supplemental_issues.csv`; отчёт — `supplemental_quality.json`. Схемы — контракт v0.4. [Качество](supplemental-quality.md), [ближайшие задачи и запрос данных](data-engineer-next-steps.md).

`source_id` производной строки ведёт к предоставленному CSV; `upstream_source_ids` — к включённым HTML/PDF, если они доступны. Наличие связей и хешей не является предметной сверкой каждого числа. Специальные коды сохраняются, версии автоматически не выбираются. Широкий лист и экспортная копия служат сверке. Месячные разности портового каботажа — `estimated`, а не направленный тоннаж коридора.

Читайте `docs/data-audit.md`: там покрытие, источники, расхождения, три варианта цели и решения для команды. `data/source_catalog.csv` удобно открыть в Excel/Google Sheets (UTF-8 с BOM); это каталог, а не готовый датасет. В `data/source_registry.json` находятся паспорта реальных оригиналов с датой и SHA-256.

Главный CSV — **`data/processed/candidate_observations.csv`**, 18 годовых строк узкой линии за 2015–2023 годы. Это кандидат для обсуждения, а не принятая цель. Значения опубликованы источником, но сопоставимость методики и определение массы ещё требуют проверки человеком. Основной `observations.csv` намеренно не создаётся и существующий файл с таким именем не перезаписывается.

## Воспроизвести по сохранённым оригиналам, без интернета

```bash
python -m pipeline.verify
python -m pipeline.build
python -m pipeline.verify
python -m pipeline.validate data/processed/candidate_observations.csv --registry data/source_registry.json --corridor --require-observations --observed-only
```

Первая проверка выявляет повреждение готового комплекта до пересборки. В рабочем репозитории после изменения кода или паспортов сначала нужна новая сборка; проверка старого манифеста закономерно отклонит изменённую версию.

Версия данных зависит от SHA-256 оригиналов, реестра и кода. Одинаковые входы и код дают идентичные CSV, отчёт и манифест. Произвольные папки `Downloads` и `кейс чемпионат` для работы не нужны. Сборка выбирает последний зарегистрированный снимок каждого источника, сохраняя прежние оригиналы.

## Получить исходники на новой машине

Если оригиналов нет, сначала выполните:

```bash
python -m pipeline.acquire
python -m pipeline.build
python -m pipeline.verify
```

Получение разных источников независимо: доступные файлы сохраняются даже при сбое другого источника. При любой ошибке получения код выхода — 1; детали находятся в `failures` реестра. Для сборки обязательны `hackathon_catalog`, `rosmorport_freight`, `rosmorport_ferry`; сбой дополнительного источника не подменяется нулевыми наблюдениями. У Росстата в текущем окружении была ошибка сертификата, поэтому его данные не объявлены проверенными. Проверка TLS остаётся включённой.

По умолчанию уже сохранённые снимки сверяются по хешу и повторно не скачиваются. Для намеренного обновления одного источника:

```bash
python -m pipeline.acquire --source rosmorport_freight --refresh
python -m pipeline.build
```

Сайт может обновиться: новый оригинал получит другой хеш и версию. Воспроизведение именно переданного результата требует переданных оригиналов, а не свежего скачивания. Список источников и их ограничения — `pipeline/sources.json`. Параллельно несколько экземпляров `acquire` для одного реестра не запускайте.

Для гипотез добавлены пять источников: `oboronlogistics_apr2025`, `oboronlogistics_jul2025`, `oboronlogistics_ferry_service`, `oboronlogistics_schedule_20261105`, `oboronlogistics_lkk_rules`. Прямые ссылки и назначение каждого находятся в README, разделе «Материалы для проверки гипотез». При необходимости получить только их:

```bash
python -m pipeline.acquire --source oboronlogistics_apr2025 oboronlogistics_jul2025 oboronlogistics_ferry_service oboronlogistics_schedule_20261105 oboronlogistics_lkk_rules
python -m pipeline.build
python -m pipeline.verify
```

Эти оригиналы сохраняются для исследования; направленные наблюдения и параметры сценария автоматически из них не формируются. Сводки имеют разный охват, а PDF расписания содержит план, не фактические события. Ошибка доступа к Росстату не мешает получить указанные пять источников.

Необязательный импорт предоставленного документа: `python -m pipeline.acquire --local team_concept /путь/к/документу.docx`. Он сохраняется как контекст с хешем, не используется как первоисточник целевых чисел. После импорта выполните сборку. Абсолютный путь пользователя не включается в паспорт; для запуска оригинал читается из `data/raw`.

## Импорт пользовательских таблиц

В рабочей папке и архиве уже сохранены все четыре переданных файла. Повторно импортировать их для сборки не требуется. На другой машине, имея только оригиналы, выполните последовательно:

```bash
python -m pipeline.acquire --local exports_all_jan2022 /путь/ЭК_январь_2022.xlsx
python -m pipeline.acquire --local exports_non_raw_jan2022 /путь/НЭ_январь_2022.xlsx
python -m pipeline.acquire --local exports_non_raw_non_energy_jan2022 /путь/ННЭ_январь_2022.xlsx
python -m pipeline.acquire --local customs_transit_2204 /путь/2204_tranzit_EN.xls
python -m pipeline.build
python -m pipeline.verify
```

При пробелах в пути заключите весь путь в кавычки. Метаданные и ожидаемые имена заданы в `pipeline/local_sources.json`; оригинал копируется без изменений, SHA-256 включается в реестр. Организация и ссылка на публикацию пока неизвестны, паспорт честно сохраняет этот пробел. Если wheel из комплекта отсутствует, для XLS предварительно установите группу зависимостей `data` командой выше. Базовые источники для общей сборки также должны быть сохранены, как описано в предыдущем разделе.

Экспортные таблицы преобразованы из широкого вида в строки «территория × группа предприятий × месяц × вид экспорта». Пустые листы исключены, реальные нули сохранены. Периоды читаются из колонок: **январь 2021 и январь 2022**, а не все годы из общего заголовка. Масса уже указана в тоннах, стоимость в тыс. USD дополнительно переводится в USD. Вложенные виды экспорта, итоги и подгруппы, страну и регионы складывать нельзя.

В транзите строка — товар декларации, а не отдельная перевозка. Кг делятся на 1000; отсутствующий нетто остаётся пустым; общая масса декларации не дублируется по товарам. Проверяются даты, повторные строки и конфликтующие ключи. Суммы месячной сводки описывают записи выборки и не доказывают уникальный грузопоток коридора. `water` означает неразделённый морской/речной транспорт, `rail` — железную дорогу без подтверждения сухопутного пересечения; это отдельные категории контекстной таблицы.

Идентифицирующие поля участников, реквизиты транспорта и исходные номера деклараций в очищенный CSV не включены. Хеш декларации позволяет связывать товары одной декларации. Оригинал с исходными полями остаётся локальным, входит в архив и передаётся согласованным получателям. Отчёт о покрытии, диагностике и приёмке — [tables-quality.md](tables-quality.md).

Пробелы и неразрывные пробелы удаляются только при чтении чисел, десятичная запятая заменяется точкой. Расчёты массы выполняются через `Decimal`. Тысячи тонн умножаются на 1000; фуры, вагоны и контейнеры в тонны не переводятся. Прочерк сохраняется в исходном поле, нормализованное значение остаётся пустым. Коды `CD`, `ND`, `-77777777`, `-99999999` требуют паспорта и отклоняются этим парсером, а не автоматически заменяются. При пропаже/повторе подписанной ячейки или изменении структуры таблицы сборка останавливается.

## Проверки и передача

Регрессионные тесты репозитория: `python -m unittest discover -s tests -v`. Они используют только явно тестовые данные во временных папках, сеть не нужна. Проверяются направление, единицы, потеря пропусков, структура источника, конфликты, порча оригиналов и воспроизводимость сборки.

Чтобы подготовить локальный архив для согласованного командой хранилища:

```bash
python -m pipeline.package
```

Команда сначала проверяет комплект, затем сохраняет ZIP и файл SHA-256 в `reports/generated/`. В архиве есть оригиналы из паспортов, подготовленные CSV, реестр, код и инструкции; при наличии включаются README со ссылками на источники, карточки гипотез и ноутбук `notebooks/dataset_overview.ipynb` с инструкцией. Ноутбук хранится без результатов; для него отдельно устанавливают группу зависимостей `notebooks`. Архив не публикуется автоматически. Тесты репозитория в архив не включены; проверка получателем выполняется через `pipeline.verify` и повторную сборку. После распаковки в пустую папку выполните команды офлайн-воспроизведения выше. Сверьте SHA-256 архива с отправителем по согласованному каналу.

В Git остаются код, каталог ссылок, паспорта и документация. Оригиналы, промежуточные и обработанные таблицы, архивы не коммитятся. Для передачи ML Lead нужны кандидат, покрытие, отчёт и манифест; аналитику — ограничения источников и отдельные параметры объектов; Fullstack — контракт v0.4 и предупреждения. В v0.3 добавлены отдельные экспортные и транзитные таблицы с полями единиц, географии и происхождения; схема наблюдений и HTTP API сохранены.

## Приёмка человеком и следующие решения

Человек сверяет все 18 исходных ячеек, подписи и единицы короткого ряда; проверяет направление относительно Калининграда, определение массы (включая возможную тару) и охват операторов; разбирает расхождения с терминалом. Имя проверившего, дата и результат вносятся в командный реестр решений после реальной проверки. ИИ и автоматические тесты не отмечаются как человеческая приёмка.

ML Lead и Team Lead утверждают цель и временной шаг; Data Engineer с аналитиком согласуют классификатор и границы охвата; аналитик с командой выбирает две гипотезы и необходимые параметры. До решения можно продолжать аудит новых источников, сохраняя их отдельно. API и существующий сценарный расчёт этим конвейером не изменяются.
