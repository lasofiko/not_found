# Контракты v0.7

## Месячный каботаж и годовые эксперименты v0.7

По запросу пользователя добавляется отдельная модель общего каботажа порта Калининград, без OD, маршрута и направлений. Это `target_id: kaliningrad_port_cabotage`, `metric: cargo_handling`, `period_granularity: month`, `unit: tonnes`, `direction: null`. Она не заменяет годовой прогноз линии. Общий README и существующий указатель `models/latest.json` сохраняются.

`python -m ml.port_run [--end-period YYYY-MM]` проверяет действующий комплект, готовит 36 месячных значений 2023–2025, обучает модели и выпускает отдельный отчёт. Для 2023 используются только однозначные сравнительные строки публикаций 2024; для 2024–2025 — основной год публикации. Выбор роли зафиксирован, конфликтующие версии внутри роли отклоняются. Разности считаются только между соседними накоплениями одного года и одинакового охвата; январь равен январскому накоплению. Отрицательные, пропущенные и неоднозначные значения останавливают подготовку. У каждой строки `status: estimated`, формула, текущая и предыдущая ячейки/источники, их роли и SHA-256. Выход `training_series.csv` находится в отдельном каталоге отчёта; исходные CSV конвейера не переписываются.

Историческая доступность: `publication_year/month` реестра — период отчёта, **не дата публикации**. Из официального URL `/uploads/YYYY/MM/` получается консервативная верхняя граница доступности — последний день месяца размещения. Это оценка доступности по архивному URL, не доказанная точная дата; метод и ограничение сохраняются. Без такого URL/явной даты источник отклоняется. `available_by` месячной разности — максимум дат обоих накоплений. На каждом срезе используются только строки с `available_by <= issued_at`. Недоступные исторические месяцы остаются пустыми, обучающие окна признаков с ними пропускаются. От последнего известного месяца до целевого строятся рекурсивные промежуточные прогнозы; `model_steps` может быть больше календарного горизонта 1/3. Для seasonal naive достаточно известного одноимённого месяца прошлого года; отсутствие ненужного промежуточного месяца не заменяется нулём.

Кандидаты: `naive`, `seasonal_naive`, `ridge_0.1`, `ridge_1`, `ridge_10`. Ridge — L2-регрессия со свободным intercept, обучаемая на стандартизованных внутри обучающего окна признаках `lag_1, rolling_mean_3, month_sin, month_cos`; последние вычисляются по календарю. Регрессия реализована на NumPy, состояние переносится в JSON. Экономические индексы остаются кандидатами факторов, в backtest не включаются.

Development: прогнозные месяцы январь–июнь 2025, holdout: июль–декабрь 2025. Горизонт 1 — шесть месячных срезов на этап; горизонт 3 — два непересекающихся блока на этап (январь/апрель и июль/октябрь). Дата выдачи — конец месяца перед первым целевым месяцем. Выбор по средней MAE development горизонта 1, при равенстве порядок кандидатов выше; ошибка на срезе исключает кандидата из выбора. Горизонт 3 и holdout не меняют выбор. MAE/WAPE считаются относительно восстановленного ряда отдельно по этапам и горизонтам; это не точность по наблюдённому тоннажу коридора.

Итоговое обучение — все 36 месяцев, `forecast_origin: 2025-12`. Доступность полного набора — январь 2026 по URL декабрьского отчёта; первая оценка января 2026 имеет `timing: nowcast`, последующие — `forecast`. Это явно подписывается, чтобы не выдавать январскую оценку за прогноз, выпущенный в декабре. По умолчанию выводятся январь–декабрь 2026; максимальная дата — декабрь 2030, месяцы после первых 12 помечаются экспериментальной экстраполяцией. Интервалы 80/95% — 2000 рекурсивных симуляций центрированных ошибок обучения, seed 42, неотрицательная масса; параметры модели фиксированы, покрытие интервалов не подтверждено.

`from ml import forecast_port; forecast_port(end_period="2026-12")` читает отдельный проверенный JSON-артефакт и возвращает версии, охват, модель/признаки, прогнозную точку, дату доступности, оценки с интервалами, происхождение и предупреждения. Неизвестная дата, повреждённый/отсутствующий артефакт отклоняются. Указатель — `models/port/latest.json`; чужой годовой указатель не меняется. Артефакты/CSV/HTML/манифест вне Git. Повторный запуск одинаковых входов даёт те же версии и байты.

`python -m ml.line_experiment` создаёт второй отдельный отчёт: история с 2015 и с 2011, одинаковые development 2020–2021 и проверки 2022–2023. Дополнительные 2011–2014 читаются из того же проверенного оригинала, направления и единицы сохраняются. Сравниваются независимые модели направлений и прогноз суммы с долями суммарных масс только обучающих лет. Метод агрегата выбирается по MAE двух направлений на development; доли фиксируются на каждом обучающем окне. Это исследовательская проверка, не обновление существующей модели. Точные исторические даты публикации годовых фактов неизвестны, поэтому годовая проверка ретроспективная по периодам, не доказанная имитация реального времени. Обе исходные гипотезы DOCX обсуждаются отдельно от ошибок прогноза: ожидание, свободная вместимость и экономия не оцениваются без заявок/рейсов/расходов.

## Отчёт чувствительности v0.6

`python -m ml.sensitivity` создаёт отдельный автономный HTML-отчёт, CSV/JSON расчётов и манифест в `reports/generated/sensitivity/<report_version>/`. Команда читает проверенный JSON модели без переобучения. Отчёт показывает оба направления по отдельности и доступные прогнозные годы 2024–2030. Статус результатов — `scenario`; версии данных/модели и источники базового прогноза сохраняются. Сам прогноз сохраняет статус `forecast` и не меняется при выборе сценарных параметров.

Три изменяемых допущения задаются в процентах от точечного прогноза выбранного направления/года: `demand_pct` (60–180, шаг 10), `capacity_pct` (60–160, шаг 10), `capacity_delta_pct` (0–60, шаг 10). Это шкала демонстрации, **не темп годового роста, не измеренная мощность и не оценённое моделью влияние**. Нагрузка `D = forecast × demand_pct / 100`, исходная возможность `C = forecast × capacity_pct / 100`, прибавка `ΔC = forecast × capacity_delta_pct / 100`. Пользователь видит значения и в тоннах за год. По умолчанию выбран 2027 год, если он входит в горизонт модели, иначе первый доступный год; допущения — 120%, 100%, 20%.

Общий расчёт в `backend/scenarios.py`: `baseline_shortfall_tonnes = max(0, D − C)`, `scenario_capacity_tonnes = C + ΔC`, `scenario_shortfall_tonnes = max(0, D − C − ΔC)`, `shortfall_reduction_tonnes = baseline_shortfall − scenario_shortfall`, `scenario_spare_capacity_tonnes = max(0, C + ΔC − D)`. Пустые, отрицательные, бесконечные значения и переполнение отклоняются. Возможность сверх нагрузки не означает дополнительный перевезённый груз.

`sensitivity.csv` содержит `direction,period,period_granularity,mode,route_id,status,unit,demand_pct,capacity_pct,capacity_delta_pct,forecast_reference_tonnes,demand_tonnes,capacity_tonnes,capacity_delta_tonnes,baseline_shortfall_tonnes,scenario_capacity_tonnes,scenario_shortfall_tonnes,shortfall_reduction_tonnes,scenario_spare_capacity_tonnes,assumption_source,data_version,model_version`. JSON хранит те же результаты компактными массивами с явным списком `fields`, паспортом допущений и исходными прогнозами. Все сочетания вычисляются в Python; JavaScript выбирает готовые результаты и отображает графики. Одновременная реализуемость двух направлений общим флотом не моделируется; возможности направлений нельзя считать независимыми подтверждёнными ресурсами и суммировать.

В отчёте есть сравнение до/после, чувствительность к нагрузке, карта дефицита по нагрузке и прибавке возможности, условные численные примеры и пояснение обучения на 18 наблюдениях (9 на направление). Тарифы, число судов, CAPEX/OPEX и полный цикл доставки не рассчитываются без методики и параметров. Манифест фиксирует SHA-256 файлов, модель, код и статус человеческой проверки `pending`; расчёт не подтверждает принятые командой транспортные действия.

## Экспериментальный ML-прогноз v0.5

По решению пользователя первая ML-демонстрация использует годовой тоннаж конкретной паромной линии Усть-Луга — Калининград, два направления отдельно, 2015–2023. Это ограничение демонстрации, не утверждение полного покрытия коридора или человеческой приёмки методики источника. Исходный манифест данных и `target_selection: pending` не переписываются.

`python -m ml.run --end-year 2030` проверяет комплект через `pipeline.verify`, читает только включённый в манифест `candidate_observations.csv`, выполняет временную проверку, выбирает метод для каждого направления и выпускает прогноз. При изменении CSV, конфигурации или кода модель получает другую `model_version`. Прогнозная точка — последний наблюдённый год 2023; 2024–2030 остаются прогнозом, даже если календарно уже прошли. Сценарная потребность не вычисляется из тоннажа автоматически.

Модели: `naive`, `drift`, `ses` (ETS(A,N,N), без сезонности и тренда). Предварительные проверки: 2015–2019 → 2020, 2015–2020 → 2021; выбор по минимальной средней MAE, при равенстве предпочтение в порядке `naive,drift,ses`. Настройки оцениваются только внутри обучающего окна. Выбор фиксируется до проверки 2015–2021 → 2022 и 2015–2022 → 2023; после этих проверок алгоритм не переназначается. Ошибки/несходимость подгонки выводятся явно; метод с неуспешной предварительной проверкой не участвует в выборе.

`backtest_predictions.csv`: `direction,model_id,stage,train_start,train_end,period,horizon_years,actual_tonnes,predicted_tonnes,error_tonnes,absolute_error_tonnes,fit_status,warning`. `stage`: `development|holdout`; `error_tonnes = predicted - actual`. `metrics.json` содержит MAE (тонны), WAPE (%), количество проверок и ошибок подгонки для каждого направления/метода/этапа. WAPE при нулевой сумме фактов — `null`, не ноль. Результаты 2022–2023 показываются отдельно, горизонт проверки — один год.

`ml.forecast(direction="inbound", end_year=2030, *, root=..., model_path=None)` загружает последний локальный проверенный артефакт модели. Ответ: `status: forecast`, `data_version`, `model_version`, `scenario_id: null`, `generated_at`, `geography`, `direction`, `cargo_group`, `mode: sea`, `metric: cargo_mass`, `unit: tonnes`, `forecast_origin`, `training_period`, `observations`, `selected_model`, `predictions`, `provenance`, `warnings`. Каждая строка `predictions`: `period,period_granularity: year,horizon_years,value,interval` с `interval["80"]` и `interval["95"]` (`lower,upper`). Неподдерживаемое направление, пустая/повреждённая модель и год вне 2024–2030 отклоняются с русским сообщением.

Точечные значения и нижние/верхние границы ограничиваются неотрицательной областью с явным предупреждением при изменении. Для naive и drift используются аналитические нормальные интервалы случайного блуждания (среднеквадратичные разности; для drift — остатки относительно дрейфа и поправка на оценку дрейфа); для SES — аналитическая дисперсия ETS(A,N,N). Интервалы условны относительно модели, их покрытие на девяти точках не подтверждено; они не учитывают неизвестные будущие ограничения и не доказывают точность до 2030.

Артефакт `models/<model_version>/model.json` сохраняет параметры трёх семейств без pickle, обучающие значения двух направлений, версии библиотек/кода/данных, конфигурацию и происхождение. Хеш артефакта фиксируется в `models/latest.json`; повреждение отклоняется. Отчёты `reports/generated/ml/<model_version>/`: прогноз CSV/JSON, backtest, метрики, карточка модели, графики, манифест хешей. Реальные данные, модели и отчёты остаются вне Git. HTTP API и frontend в этом этапе не меняются; Fullstack получает функцию прогноза и пример ответа.

## Локальные комплекты и частичная сборка v0.4

`pipeline.acquire --local-dir PATH` импортирует известные книги, документы и ZIP из указанного каталога без скачивания. Имена сопоставляются в Unicode NFC. Повторный импорт восстанавливает отсутствующие байты и сохраняет паспорт снимка; одинаковые вложения архивов не размножаются. `acquisition_locations` в паспорте — список `{parent_source_id, archive_member}`. `upstream_source_ids` связывает подготовленный CSV с включёнными первоисточниками; внешний URL без сохранённого оригинала остаётся только ссылкой. Внутренние манифесты проверяются до регистрации вложений. Небезопасные пути ZIP отклоняются.

`pipeline.build --available-only` разрешает отсутствие зарегистрированных оригиналов, но не повреждение существующих. Без флага проверка остаётся строгой. Манифест содержит `build_scope: full|available_only`, `unavailable_source_ids`, фактически доступные `inputs`, `table_rows` всех выпущенных CSV и `target_selection: pending`. Используется последний зарегистрированный снимок источника; отсутствующий новый снимок не заменяется старым молча. `verify` и `package` проверяют/передают входы манифеста; частичный комплект не объявляется полным. Каталог из Git сохраняется, если оригинал Google-таблицы недоступен; его хеш фиксируется, статус — `catalog_original_unavailable`. Сборка не использует оставшиеся CSV предыдущей версии.

`regional_indicators.csv` и его подвыборка `regional_freight.csv`: `indicator_code,indicator_name,section,subsection,geography,period,period_granularity,original_value,value,original_unit,unit,conversion_factor,source_title,source_version,comment,quality_flags,status,review_status,source_id,source_locator,data_version`. Основной источник — лист «Все_данные_parquet». `value` пуст для специальных кодов; код сохраняется в `original_value`. Значения метаданных `CD`/`ND` не удаляют наблюдение. Массы в млн т переводятся в т, транспортная работа в млн т·км — в т·км; прочие единицы сохраняются. Разные издания сохраняются; повторы ключа «код × подраздел × год × нормализованная единица» и расхождения помечаются, версия автоматически не выбирается. Подвыборка содержит грузовые автомобильные перевозки, грузооборот и железнодорожные отправления. История до 2015 года — контекст, не молчаливое изменение горизонта проекта.

`supplemental_freight.csv`: `series_id,period,period_granularity,mode,direction_scope,cargo_group,transport_form,measurement_scope,operator,metric,original_value,original_unit,value,unit,conversion_factor,precision,status,formula,review_status,quality_flags,quality_note,source_id,upstream_source_ids,source_locator,source_url,data_version`. `direction_scope`: `inbound|outbound|both|unknown`; `precision`: `as_published|rounded|lower_bound|approximate`. Это раздельные ряды публикаций и импортированных CSV, не полный коридор. `review_status: pending` означает отсутствие человеческой приёмки. Число «более X» хранит нижнюю границу, а не точную массу. Группы грузов и формы перевозки не смешиваются. Показатели LTG «международные», «весь транзит», «коридор» хранятся отдельно; произведение округлённых величин — отдельный `estimated` с формулой и ссылками. CSV из архивов — предоставленные производные, первичные HTML/PDF доступны по связям; наличие связи и хеша не является проверкой каждого числа.

`port_cabotage_cumulative.csv`: `period,period_granularity,port,operator,cargo_group,original_cargo_group,measurement_scope,original_value,original_unit,value,unit,conversion_factor,status,precision,review_status,source_id,source_locator,data_version`. `period` — конец накопления с января; гранулярность `year_to_date`. Сохраняются год строки (включая сравнительный год), версия публикации, портовые итоги и операторы с отдельным `measurement_scope`. `original_cargo_group` сохраняет исходную подпись; `cargo_group` убирает переносы/лишние пробелы и соединяет перенос слова «нефтепродукты». Проценты не становятся тоннами. Номенклатуры и уровни не суммируются между собой.

`port_cabotage_monthly.csv` имеет те же поля и дополнительно `previous_source_id,formula`; гранулярность `month`, статус `estimated`. Разность вычисляется только между соседними месяцами одного года, для одной единицы, строки/уровня и номенклатуры, по основным годам публикаций. Январь равен январскому накоплению. При пропуске, отрицательной разности или неоднозначной версии месячный результат не выпускается; причина попадает в `supplemental_issues.csv`. Сравнительные значения предыдущего года сохраняются только в накопительной таблице.

Пустые `original_value`, `original_unit` и `conversion_factor` в месячной таблице — ожидаемая неприменимость: отдельного опубликованного месячного числа нет, оно вычислено из накоплений. Результат хранится в `value`, единица — в `unit`, расчёт — в `formula`. Это не отсутствие массы. В январе используется январское накопление; `previous_source_id` тогда тоже неприменим. Наблюдение/оценка всегда различаются по `status`.

`border_crossings.csv`: `period,crossing,direction_label,truck_crossings,unit,status,review_status,source_id,source_locator,source_url,data_version`. Единица — пересечения грузовых автомобилей; не тонны и не присвоенное направление коридора.

`supplemental_issues.csv`: `dataset,source_id,source_locator,issue,related_locator,details`. `supplemental_quality.json` хранит профили, сверку широких листов/экспорта, пропуски, конфликты и правила. `freight_coverage.csv` содержит оценку покрытия `sea,rail_land,road,air` и ограничения, без искусственных рядов. Факторы без даты исторической доступности остаются кандидатами вне модельного `factors.csv`. HTTP API и строгая схема наблюдений сохраняются.

## Таблица наблюдений

UTF-8 CSV, одна строка на период × OD × направление × вид × группу. Обязательные поля:

`period,period_granularity,origin,destination,direction,mode,cargo_group,value_tonnes,status,source_id`

`period`: `YYYY-MM` для месяца или `YYYY` для года; `direction`: `inbound` (в область) / `outbound` (из области); `mode`: `sea`, `rail_land`, `road`, `air`; `status`: `observed`, `estimated`, `synthetic`. `source_id` ведёт к паспорту и оригиналу. Дополнительные поля: `route_id`, `in_wagon_on_ferry`, `quality_note`, `data_version`. `value_tonnes` — неотрицательное число или пустое значение, если наблюдения нет. Ключ и правила агрегации утверждаются после выбора целевого ряда. Один физический груз нельзя дублировать между `sea` и `rail_land`.

Числа в примерах схемы отсутствуют намеренно. Отсутствующее наблюдение — пустая ячейка, не ноль. Годовой источник не превращается в двенадцать месячных фактов.

## Передача данных и аудит источников

`data/source_catalog.csv` — каталог ссылок, а не проверенных фактов: `catalog_id, title, description, tracks, url, purpose, priority, review_status, limitations`. Названия и описания сохраняются как в предоставленной Google-таблице. `purpose`: `target_candidate`, `factor`, `scenario_parameter`, `reference`; `review_status: discovered` означает, что файл ещё не проверен, `index_saved` — сохранена страница раздела, но не проверены её наборы. Назначение источника не заменяет статус значения. Ошибки получения сохраняются в массиве `failures` реестра.

`data/source_registry.json` содержит `schema_version` и массив `artifacts`. Паспорт скачанного файла включает `source_id`, `source_key`, `organization`, `url`, `resolved_url`, `downloaded_at` (ISO 8601 с часовым поясом), `local_path` относительно корня проекта, `sha256`, `content_type`, `encoding`, `purpose`, `period`, `geography`, `direction`, `mode`, `cargo_groups`, `metric`, `original_unit`, `limitations`, `usage_rights`. `source_id` идентифицирует неизменённый снимок: `<source_key>__<первые 12 символов SHA-256>`. Повторное скачивание новых байтов добавляет паспорт, старый оригинал остаётся. `null` в паспортных полях означает «не установлено», а не ноль. Дата скачивания не является датой публикации или исторической доступности признака.

Новый конвейер пишет **`candidate_observations.csv`**, соответствующий таблице наблюдений, но не утверждает его основной целью модели. `observed` означает опубликованное наблюдение названного показателя; это не подтверждение полного покрытия коридора или методологической сопоставимости. `observations.csv` автоматически не создаётся. Выбор цели и перенос кандидата в основной набор — отдельное решение команды.

Для узкой паромной линии используются OD `ust_luga` и `kaliningrad_port`, `route_id: ust_luga_kaliningrad_ferry`, `mode: sea`. Выгрузка в Калининграде → `inbound`, погрузка → `outbound`. `cargo_group: Все грузы (без разбивки источника)` — техническая метка агрегата, а не утверждённый классификатор. Дополнительные поля `source_locator,original_value,original_unit,conversion_factor,quality_note,data_version` обеспечивают трассировку ячейки и преобразования. `in_wagon_on_ferry` остаётся пустым для смешанного агрегата; это не сухопутная железная дорога. Значения разных лет, строк терминала, флота и линии не складываются.

`context_observations.csv` хранит неподходящие для направленной цели показатели: `series_id,period,period_granularity,geography,direction,mode,metric,original_value,original_unit,conversion_factor,value_tonnes,status,source_id,source_locator,quality_note,data_version`. Неустановленное направление — пустое поле. Прочерк сохраняется в `original_value`, `value_tonnes` остаётся пустым: значение прочерка требует уточнения у источника. Никакой нормализации TEU, вагонов и автомобилей в тонны нет.

`scenario_parameters.csv`: `parameter_id,object_id,metric,value,unit,period_basis,valid_from,valid_to,source_id,source_locator,quality_note`. Заявленная мощность — параметр объекта, не факт перевозки и не доступная мощность всей цепочки; неизвестные даты действия пусты.

`factors.csv`: `factor_id,period,value,unit,geography,available_at,lag_periods,source_id,quality_note`. Пока цель не выбрана, таблица содержит только заголовок. Признак без подтверждённой исторической доступности нельзя использовать в backtest.

`coverage.csv` описывает каждый извлечённый ряд: `dataset,series_id,period_granularity,direction,mode,first_period,last_period,rows,non_missing,missing_periods_within_range,source_id`. Полнота внутри диапазона ряда не означает полноты матрицы коридора. `build_manifest.json` фиксирует хеши входов/выходов, версию конвейера и статус `target_selection: pending`. `transformation_log.json` фиксирует правила обработки и предупреждения. Повторная сборка тех же оригиналов даёт те же байты результатов.

`data/interim/reconciliation.csv` содержит `period,line_sum_tonnes,terminal_cabotage_tonnes,difference_tonnes,source_id`. Разность «каботаж терминала минус сумма направлений линии» — диагностический расчёт, не ещё одно наблюдение перевозки. Неравенство фиксируется как вопрос об охвате/методике, без автоматической корректировки.

Проверка `pipeline.validate` дополнена календарными периодами и защитой от повторов. `--registry` проверяет паспорта, SHA-256 и ссылки строк на источники; `--corridor` проверяет известные OD коридора и направление; `--require-observations` отклоняет пустой набор; `--observed-only` исключает расчётные и синтетические цели. Совпадающие ключи не суммируются автоматически: ключи и агрегацию утверждает команда, конфликт направляется на разбор.

`python -m pipeline.build` собирает офлайн-комплект из сохранённых оригиналов. `python -m pipeline.verify` проверяет хеши реестра, оригиналов, кода и выходов, происхождение строк и единицы без изменения файлов. `python -m pipeline.package` сначала выполняет эту проверку, затем создаёт локальный ZIP и SHA-256, без внешней отправки. HTTP API не изменён; новые таблицы не подключаются к прогнозу автоматически.

## Дополнительные пользовательские таблицы v0.3

Файлы `ЭК_январь_2022.xlsx`, `НЭ_январь_2022.xlsx`, `ННЭ_январь_2022.xlsx`, `2204_tranzit_EN.xls` импортируются командой `pipeline.acquire --local KEY FILE` с паспортами из `pipeline/local_sources.json`. Оригинальное имя сохраняется в `provided:` URL. Организация-составитель и права на исходные выгрузки не подтверждены. Байты оригиналов сохраняются в `data/raw`, в Git они не попадают.

`exports_clean.csv` — одна строка на источник × географию × группу предприятий × месяц: `export_scope,export_scope_label,reporting_geography,geography_level,enterprise_group,period,period_granularity,enterprise_count,weight_tonnes,trade_value_thousand_usd,trade_value_usd,status,source_id,source_locator,quality_note,data_version`. `export_scope`: `all_exports`, `non_raw_exports`, `non_raw_non_energy_exports`. Это вложенные показатели: они не складываются между собой; строки «Всего» не складываются с подгруппами, страна/округа/регионы не складываются друг с другом. Веса и деньги — разные столбцы; доллары не переводятся в рубли без источника курса. `exports_kaliningrad.csv` — фильтр географии «КАЛИНИНГРАДСКАЯ ОБЛАСТЬ», без изменения показателя и без назначения направления `outbound` коридора. Фактические периоды берутся из заголовков столбцов, а не общего заголовка книги или имени файла.

`export_growth_checks.csv` хранит диагностическую сверку: `export_scope,reporting_geography,enterprise_group,metric,base_period,current_period,base_value,current_value,reported_growth_index_pct,calculated_growth_index_pct,difference_pp,check_status,source_id,source_locator`. «Темп роста, %» означает индекс отношения текущего значения к базовому, а не процент прироста. При нулевой базе расчётный индекс пуст; опубликованное значение сохраняется. Расхождения из-за округления исходных чисел отмечаются, а не исправляются. Двоичные хвосты процентов устраняются только если отличаются от ближайшей десятой не более чем на `1e-9`; исходный XLSX остаётся неизменным.

`transit_items_clean.csv` — товарные строки деклараций, **не уникальные физические отправки**: `record_id,declaration_id_hash,item_number,declaration_type,movement_type,registered_date,completed_date,transit_days,origin_country_code,destination_country_code,departure_customs_code,destination_customs_code,departure_customs_name,destination_customs_name,departure_transport_code,actual_transport_code,departure_mode,actual_mode,commodity_code,item_gross_kg,item_gross_tonnes,item_net_kg,item_net_tonnes,item_invoice_usd,quality_flags,status,source_id,source_locator,data_version`. Названия/адреса участников, ИНН, номера контейнеров и транспорта в очищенную таблицу не включаются. Идентификатор декларации заменён SHA-256 для связывания её товарных строк. Общий вес декларации не размножается по товарам. Технический ключ «декларация × номер товара» проверяется на конфликты, но не считается идентификатором физической отправки.

`departure_mode` / `actual_mode`: `road`, `rail`, `water`, `air`, `other`, либо пусто; это вид транспорта в точке оформления/из исходной подписи, а не присвоение коридору `rail_land`. `water` сохраняет неоднозначность исходного «Морской/речной транспорт». География хранится как в таможенной выгрузке; страна RU не доказывает Калининградскую область или нужную пару территорий. Пропущенный вес нетто не восстанавливается по брутто.

`transit_monthly_summary.csv`: `period,origin_country_code,destination_country_code,actual_mode,commodity_prefix,item_rows,declarations,known_gross_rows,item_gross_sum_tonnes,known_net_rows,item_net_sum_tonnes,source_id,quality_note`. Это сумма товарных записей данной выгрузки после удаления только точных повторов, а не тоннаж коридора. Число деклараций не аддитивно между группами. Строки разных деклараций могут относиться к одним и тем же физическим грузам на разных этапах транзита.

`table_quality.json` фиксирует количество строк, точные повторы, конфликты ключей, пропуски, периоды, покрытие и правила. `table_row_issues.csv`: `dataset,source_locator,issue,related_locator`; конфликты остаются в очищенных данных с флагом, точные повторы исключаются со ссылкой на сохранённую строку. `docs/tables-quality.md` — отчёт для человека. Эти выходы включаются в общий манифест и архив. Существующая таблица наблюдений и HTTP API не меняются; новые таблицы — контекст до предметного согласования.

Для старого XLS используется `xlrd==2.0.2`, объявленный в дополнительной группе зависимостей `data`. Для офлайн-сборки допускается проверенная по SHA-256 копия официального wheel в реестре с `source_key: xlrd_reader`; исходники и лицензия BSD находятся внутри wheel. Если XLS не зарегистрирован, сборка прежнего набора остаётся доступной на стандартной библиотеке.

## Сценарный API

`POST /api/v1/scenarios/capacity` принимает `demand_tonnes`, `capacity_tonnes`, `capacity_delta_tonnes` (конечные неотрицательные числа, один и тот же период), `period`, `assumption_source`. Возвращает `baseline_shortfall_tonnes`, `scenario_capacity_tonnes`, `scenario_shortfall_tonnes`, `shortfall_reduction_tonnes`, `scenario_spare_capacity_tonnes` (добавлено в v0.6), `status: scenario` и предупреждение. Некорректные числа и переполнение суммы возвращают HTTP 422. Расчёт общий с отчётом чувствительности. Это чувствительность к входным параметрам, не прогноз и не эффект утверждённой инвестиции.

Будущий результат прогноза должен включать `data_version`, `model_version`, `scenario_id`, `generated_at`, `geography`, `direction`, `cargo_group`, `mode`, `period`, `metric`, `value`, `unit`, `interval`, `provenance`, `warnings`. Схема будет уточнена ML Lead и Fullstack до интеграции.

## Единицы

База: т, руб., ч, км; транспортная работа — т·км. На графике видны период и единица. Тысячи тонн — только формат отображения. Вместимость в т/сутки сравнивается с т/месяц после пересчёта по конкретному числу рабочих дней. TEU, вагоны и рейсы не переводятся в тонны без документированной загрузки.
