# Единый Frontend FloCast — локальная проверка 11 ноября 2026

## Почему раньше открывались разные страницы

FastAPI на `/` и `/capacity` отдавал отдельный frontend/capacity.html.
React-сборка из frontend/dist была смонтирована только на `/dashboard/`,
без проверки соответствия текущим исходникам. Vite запускал React отдельно.
Поэтому адрес и давность сборки определяли, какой интерфейс увидит пользователь.
Это были разные точки входа, а не переключение темы одного приложения.

## Основной интерфейс и точка входа

Утверждённым и единственным основным интерфейсом оставлено существующее React-
приложение с контейнеровозом, FloCast, светлой серо-сиреневой темой, фиолетовыми
кнопками, Sidebar, показателями и AI-панелью. Основные стили App.css/index.css,
типографика, main.tsx и фотографии не изменялись. Добавлен только встроенный
раздел калькулятора, использующий те же панели и цветовые переменные.

Вход: frontend/index.html → frontend/src/main.tsx → App.tsx.
Hero, Sidebar, темы, фильтры, карта, сценарии и AI-панель формирует App.tsx;
TransportGallery.tsx — транспорт; ForecastCharts.tsx — существующие графики.

## Адреса и архитектура

- Главная: http://127.0.0.1:8000/ — HTTP 200, этот же адрес остаётся в строке браузера.
- Разработка: http://127.0.0.1:5173/ — тот же React через Vite.
- Калькулятор: /#capacity, без отдельного HTML-интерфейса.
- Старые /dashboard/ направляются на корень; /capacity и /capacity.html — на /#capacity.
- /config.json содержит фактический apiBase. Vite проксирует API к backend.
- API и /docs зарегистрированы до SPA. Неизвестный API сохраняет JSON 404,
  неверный метод известного API — 405; отсутствующие ресурсы не получают index.html.

Схема: React → FastAPI → существующий ForecastService → ML и артефакты.
Калькулятор → прежний POST /api/v1/scenarios/capacity → backend.scenarios.capacity_balance.
AI-панель → серверные /api/v1/llm/* → настроенный провайдер.
Новая модель и вычисления во Frontend не создавались.

Production build создаёт dist/build-info.json с отпечатками исходников,
public, конфигурации и index.html. Backend отклоняет старую или непроверенную
сборку с 503 и командой build, сохраняя работоспособность API. Новый dist
обнаруживается без перезапуска. При запуске из репозитория сохраняйте src/public
и конфигурацию рядом с dist для сверки. HTML исключён из PWA precache.

## Запуск

Команды из корня проекта, в активном Python-окружении. Первичная установка:

```powershell
python -m pip install -e ".[dev]"
npm --prefix frontend ci
```

Разработка, два терминала:

```powershell
# Терминал 1
python -m uvicorn backend.app:app --reload
# Терминал 2
npm --prefix frontend run dev
```

Если терминал уже находится в frontend, используйте npm ci и npm run dev без
--prefix frontend: иначе npm ищет frontend/frontend. Не закрывайте запущенный
сервер Vite во время работы. В момент диагностики на 5173 не было слушающего
процесса; после запуска Vite страница открылась.

Демонстрация через один адрес:

```powershell
npm --prefix frontend run build
python -m uvicorn backend.app:app --reload
```

Открыть http://127.0.0.1:8000/. После изменения React повторите build.
Git не пересобирает dist. После изменения Python нужен reload/перезапуск.

## Backend, ML и ограничения

На этом Windows-компьютере настоящая годовая модель подключена: /forecasts
возвращает ready, model_version bb-ml-6237c3f27262 и семь периодов 2024–2030.
В браузере работают графики, таблица и CSV реального результата. Поддержаны
inbound/outbound и морская линия Усть-Луга — Балтийск; это не весь грузовой коридор.
Точность до 2030 года не объявляется подтверждённой. История — 2015–2023.

Существующие synthetic-примеры сохранены отдельно и явно помечены. Они не
подставляются в прогноз при ошибке. Для неподключённых регионов/городов
показатели заменяются прочерками. Модели Приморья, Камчатки, rail_land/road/air
к HTTP-прогнозу пока не подключены. Карточки транспорта остаются справочными.

LLM-провайдер на сервере не настроен: панель показывает соответствующую ошибку,
а не зависает. Для реальных ответов нужны серверные BB_LLM_*. Ключи в браузер не
передаются. Настройка внешнего провайдера в эту правку не входит.

## Проверки

- npm run lint — успешно.
- npm test — 15 прошли, один тест реального forecast CSV штатно пропущен в этом запуске.
- Отдельный запуск API-тестов с настоящим ответом модели — 4/4, включая ранее
  пропущенный CSV. Совокупно проверены все 16 существующих/добавленных frontend-тестов.
- npm run build — TypeScript, Vite и PWA успешно, без смены дизайна.
- Backend: 82 теста прошли, включая настоящие артефакты модели и новую маршрутизацию.
- Ruff check — успешно. Регрессия 405 при корневом SPA-mount исправлена и проверена.
- HTTP: корень backend отдаёт React с 200 без перенаправления, /capacity ведёт в React,
  старый /dashboard/ — на корень; неизвестный API возвращает JSON 404.
- В браузере: одинаковый Hero в Vite/backend, светлая и тёмная темы, восемь пунктов
  Sidebar, четыре транспортных диалога, загрузка фото, три графика реального прогноза.
- Карта OpenStreetMap отображается: загружены тайлы, маркер и элементы масштаба.
- Реальный CSV, скачанный браузером, побайтно совпал с createForecastReport от
  актуального API-ответа: семь лет, правильная модель и направление inbound.
- Калькулятор через backend: 100/80/+30 → исходный дефицит 20, мощность 110,
  новый дефицит 0, сокращение 20 и запас 10 т. Изменение ввода очищает результат.
- Прямая ссылка /capacity открывает форму и после асинхронной загрузки ML-таблицы:
  начальная прокрутка выполняется после получения прогноза и загрузки шрифтов.
- На ширинах 390 и 320 горизонтального переполнения нет; мобильное меню содержит
  все разделы, форма становится одноколоночной, неверный период 2027-13 невалиден.
- Выбор Приморья убирает демо-числа. Смена направления/горизонта настоящего прогноза
  работает: outbound до 2028 показывает пять периодов.
- Ошибки сети, таймаут, отмена и некорректный ответ покрыты frontend-тестами;
  отсутствие/устаревание сборки и ошибки модели проверяются backend-тестами.
