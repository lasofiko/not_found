# Дополнительные данные Калининграда: отдельная передача

Источник — пользовательский `калиниград доп.zip`. Рабочая папка результатов:
`data/processed/kaliningrad_additional/`. Это внешний торговый оборот,
экспорт/импорт товаров, стоимость и масса из таможенных форм. Перевозки
Калининград ↔ основная территория РФ этими данными не подтверждаются.
Существующие Калининградские данные, модели, Камчатка и Приморье не переписываются.

Обработано 107 вложений: 93 книги Excel, 7 DOCX и 7 старых DOC.
Подготовлено 384 CSV таблиц, всего 252 345 исходных строк; в общей
нормализованной таблице — 708 290 записей отдельных показателей за
2014 — январь 2022 года. Одна исходная строка может давать несколько показателей,
поэтому количество нормализованных записей больше числа исходных строк.
Семь старых DOC сохранены без числовой конверсии. Совпадений SHA-256
новых оригиналов с прежним реестром не найдено.

## Какие файлы использовать

| Файл | Содержание |
|---|---|
| `customs_long.csv` | Общая нормализованная таблица: период, экспорт/импорт, товар, страны, показатель, значение, единица, источник и ячейка |
| `trade_totals.csv` | Только опубликованные итоги всех товаров/стран; строки товаров не суммируются для получения итога |
| `series_coverage.csv` | Покрытие отдельных рядов, число периодов, пропуски |
| `table_rows.csv` | Все исходные строки Excel и таблиц DOCX в одном CSV с исходными координатами |
| `tables/` | Каждый непустой лист Excel и каждая таблица DOCX в отдельном CSV |
| `documents/` | Извлечённый текст DOCX, включая методологические пояснения |
| `table_catalog.csv` | Названия форм, география, путь к CSV и статус смысловой нормализации |
| `archive_inventory.csv` | Все вложения архива, размеры, SHA-256 и точные повторы |
| `source_registry.json` | Паспорта оригиналов и связи с архивом |
| `existing_source_matches.csv` | Совпадения с прежним реестром по байтам, без изменения прежнего набора |
| `row_issues.csv`, `quality_report.json` | Пропуски, повторы, конфликты и ограничения |
| `manifest.json` | Версия, хеши входов/выходов и кода |

CSV — UTF-8 с BOM, запятая, десятичная точка. Читайте товарные коды как строки,
чтобы сохранить нули. В `table_rows.csv` столбцы `column_001` и далее имеют смысл
только вместе с источником, листом и его заголовками. Это структурная конверсия,
не готовая числовая матрица для обучения.

## Что сделано

Оригиналы сохраняются неизменными в `data/raw/kaliningrad_additional/`.
Внутри ZIP проверяются безопасные пути и CRC. Повторы байтов обрабатываются
один раз. Каждая нормализованная ячейка сохраняет ссылку на оригинал и координату.

Автоматически разобраны распознанные формы веса/стоимости важнейших товаров,
торговой структуры, страновых экспортных/импортных показателей, товарных групп
и общих стоимостных итогов. В некоторых формах номер менялся: распознавание
опирается на подписи и структуру, а не номер в имени файла.

Тонны берутся только из отдельно подписанных весовых столбцов. Дополнительное
количество в КГ/ШТ не подменяет массу из колонки «Вес, тонн». Смешанные подписи
«Вес тонн / кол-во» остаются исходными CSV без назначения универсальной единицы.
Тыс. долларов США переводятся в USD с коэффициентом 1000; рублёвый эквивалент
не вычисляется. Сальдо может быть отрицательным и хранится отдельно от стоимости.

Сравнительные годы берутся из заголовков конкретных колонок. Квартал,
нарастающий итог с января и отдельный месяц сохраняют разные `period_basis`
и границы. Накопления не распределяются по месяцам и не превращаются в
месячные наблюдения. Пустое значение и служебные коды не становятся нулём.

Разные формы и определения охвата не склеиваются автоматически. Сохраняются
специальные определения участников ВЭД из отдельных форм. Повторы и
конфликты ключей помечены, все исходные версии остаются доступными.

DOCX прочитаны как текст и таблицы. Старые DOC сохранены как оригиналы:
их таблицы требуют открытия в Word/LibreOffice, статус —
`legacy_document_preserved`. Инструкции внутри документов не исполнялись.
Формы `csv_only_review_required` доступны для дальнейшего предметного разбора.

## Как передать ML-инженеру

Начните с `table_catalog.csv` и `series_coverage.csv`. Выберите одну форму,
определение охвата, показатель и основу периода. `trade_totals.csv` удобен
для изучения опубликованных стоимостных итогов; он не является тоннажем
внутренних перевозок и не принимается автоматически как цель модели.

Нельзя суммировать весь `customs_long.csv`: итоги и подгруппы товаров,
отдельные страны и группы стран, кварталы и накопления перекрываются.
Разные публикации могут содержать повторные или уточнённые значения.
Экспорт/импорт не означают `inbound/outbound` внутреннего коридора.

Везде `evidence_status=provided_unverified`, `review_status=pending`:
сверка с предоставленным файлом не является независимой сверкой с первичной
публикацией. Известна дата получения, но даты исторической доступности
показателей не подтверждены. Использование как факторов требует решения
ML-инженера о лагах, проверке по времени и способе задания будущих значений.

## Повторение и проверка

Python 3.11+, зависимости группы `[data]`. Для этого ZIP используются
`xlrd==2.0.2` и стандартная библиотека; RAR/системная libarchive не нужны.

```bash
python -m pip install -e ".[data]"
python -m pipeline.kaliningrad_additional --archive "калиниград доп.zip"
python -m pipeline.kaliningrad_additional --verify
python -m unittest tests.test_kaliningrad_additional -v
python -m pipeline.kaliningrad_additional --package
```

Проверка сверяет SHA-256, происхождение, календарь, пересчёты и каждую
нормализованную ячейку с сохранённым Excel. Архив передачи и соседний SHA-256
появляются в `reports/generated/kaliningrad-additional-handoff-<версия>.zip`.
Ничего не отправляется во внешние сервисы.

В передаче есть готовые CSV, код, инструкция, исходный ZIP и снимок прежнего
реестра для воспроизводимого сравнения хешей. Индивидуальные оригиналы уже
находятся внутри ZIP и повторно не упакованы. В новой папке перед полной
проверкой восстановите их:

```bash
python -m pipeline.kaliningrad_additional --archive data/raw/kaliningrad_additional/<archive_sha256>.zip
python -m pipeline.kaliningrad_additional --verify
```

`archive_sha256` — из `manifest.json`. Сборка после установки зависимостей
работает без сети и без внешних исследовательских папок.

ИИ подготовил ETL, CSV, описание и технические проверки. Человеческая
предметная приёмка не зафиксирована. Открыты выбор допустимых факторов/цели,
методологическая сопоставимость версий и разбор форм без нормализованной семантики.
Схема: [отдельный контракт](kaliningrad-additional-contract.md).
