# Сравнение решений FloCast

Рабочий раздел сравнивает одну сценарную нагрузку линии Усть-Луга — Балтийск
с исходной провозной возможностью и двумя явно введёнными приростами.
А — резервный паром на время ремонтов; Б — постоянный дополнительный паром.
Численные параметры пользователь задаёт самостоятельно с указанием происхождения.
Они не становятся подтверждёнными эффектами действий после расчёта.

| Возможность | Как используется |
|---|---|
| Сравнить решения | Выбрать год и направление, ввести нагрузку, исходную возможность, приросты А/Б и их источники; выполнить серверный расчёт. |
| При каких условиях этого достаточно? | Посмотреть требуемый прирост, численную сетку чувствительности и границу полного покрытия. |
| Паспорт цифры | Открыть «Источник и расчёт» у показателя; увидеть определение, формулу, единицу, охват и состояние проверки. |
| Ввоз и вывоз | Сопоставить направления одного проверенного артефакта, отделяя историю от прогноза. |
| Какие данные доступны | Проверить раздельные стадии регистрации, доступности оригинала, подготовки ряда и подключения модели. |
| Подготовить обоснование | Открыть печатную HTML-версию, сохранить числовое сравнение CSV или снимок JSON. |
| Ассистент сравнения | Задать вопрос о применённом снимке либо отдельно запустить подробный разбор. |

## Пользовательский путь

1. Открыть «Какие данные доступны» и проверить охват выбранной территории.
2. В разделе «Сравнить решения» выбрать поддерживаемую годовую линию и направление.
3. Ввести нагрузку непосредственно в тоннах либо явно выбрать прогноз и множитель
   как масштаб сценарной нагрузки. Прогноз перевезённой массы не измеряет спрос.
4. Ввести исходную возможность и приросты А/Б в тоннах за тот же год, указать
   происхождение каждого допущения. Исторический максимум не подставляется как мощность.
5. Запустить сравнение, изучить таблицу, график, пороги и паспорта показателей.
6. При необходимости включить профиль обоих направлений; изучить ограничения.
7. Сформировать обоснование и при настроенном LLM получить пояснение того же снимка.

Правка входов делает предыдущий результат неактуальным. Для экспорта и AI нужен
новый применённый снимок. Старый ответ сервера не должен заменять результат новой формы.
Кэш ограничен 128 снимками на процесс, срок — 30 минут. После истечения,
перезапуска или изменения модели необходимо выполнить сравнение заново.
Запускать приложение следует с одним серверным worker.

## Запуск

Команды выполняются из корня репозитория в уже подготовленном Python-окружении:

```powershell
npm --prefix frontend run build
python -m uvicorn backend.app:app --reload
```

Открыть <http://127.0.0.1:8000/>. Для разработки во втором терминале:

```powershell
npm --prefix frontend run dev
```

Открыть <http://127.0.0.1:5173/>. Vite использует действующую настройку API;
все новые маршруты используют `apiBase` из `/config.json`.
Первичная установка зависимостей и проверенное lock-окружение описаны в README.
Пользовательский `.env` перезаписывать не нужно.

## Источники и ограничения

Прогнозная основа — только проверенный существующий годовой артефакт линии:
история 2015–2023, прогноз 2024–2030 из точки 2023 года. Это ограниченный объект,
а не весь грузопоток Калининградской области. Модель не обучается при запросе.
Прогноз не становится наблюдением только потому, что календарный год уже прошёл.
Точность до 2030 и гарантированное покрытие интервалов не заявляются.

Профиль направлений считает доли, разность и отношение только при сопоставимом
охвате и статусе. При нулевом знаменателе относительное значение неопределено.
Разность масс не показывает свободную вместимость и не доказывает наличие
порожних обратных рейсов. Интервальные границы направлений не суммируются.

Без модели доступен прямой сценарный ввод, пороги, паспорта и экспорт.
Прогнозная нагрузка и профиль направлений показывают недоступность без подмены
синтетическими данными. Наличие Приморья или Камчатки в справочнике не означает
наличие подключённого направленного прогноза. Портовый каботаж не подменяет ряд линии.

Экспорт не пересчитывает результат. Печатная HTML-версия открывает системную
«Печать / Сохранить в PDF»; автоматическая загрузка PDF не реализуется этой кнопкой.
Выгрузки не включают исходные архивы и закрытые исторические ряды.

## AI-разбор

Обычный чат сохранён. Вопрос о сравнении использует один LLM-вызов с серверным
снимком. Кнопка «Подробный разбор» запускает три отдельных специализированных
вызова: интерпретация сравнения, анализ доказательств и критика допущений.
Сервер проверяет структуру и разрешимость ссылок, затем собирает разделы
без дополнительного LLM-вызова. Рекурсия и автоматические повторные попытки отсутствуют.

Ограничения: максимум два одновременных специализированных вызова, общий таймаут
60 секунд, ограниченные контекст и длина ответов, защита от дублирующего разбора.
Отказ специалиста даёт явно неполный результат. Смена снимка отменяет ожидание;
повтор выполняется только по действию пользователя. Ключи остаются на сервере.
Без настроенного LLM сравнение и экспорт работают, AI сообщает о недоступности.

LLM-пояснение не является независимой экспертизой или человеческой приёмкой.
Валидный JSON и корректная ссылка не доказывают истинность свободного текста.
Числа рассчитывает backend, а модель помогает объяснить результаты и ограничения.

## Проверки и человеческая приёмка

Основной контрольный пример явно синтетический: нагрузка 150 т, исходная
возможность 100 т, прирост А 20 т, прирост Б 70 т. Остаток: 50 / 30 / 0 т;
запас Б 20 т, требуемый для покрытия прирост 50 т.
Тестовые артефакты создаются во временных каталогах; платный провайдер и
настоящая сеть в обычных тестах не вызываются.

```powershell
python -m pytest backend/tests -q
python -m ruff check backend
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
python scripts/smoke.py
```

ИИ участвовал в проектировании контракта, написании кода, тестов и документации.
Автоматические проверки подтверждают проверенное поведение программы в пределах
тестовых условий. Они не заменяют сверку источников и предметных допущений человеком.
До практического транспортного решения нужны подтверждённые доступные мощности,
выработка и календарь судов, ограничения инфраструктуры, затраты CAPEX/OPEX,
операционные условия и критерий выбора. А+Б требует отдельного решения о совместимости
и отсутствии двойного учёта. Протокол человеческой проверки существующих данных
и обоснованности этих параметров остаётся задачей команды.
