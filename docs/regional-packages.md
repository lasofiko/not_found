# Новые комплекты Камчатки и Приморья

По решению команды добавлены Камчатский и Приморский края. Шесть ZIP из корня проекта обработаны отдельно от прежнего Калининградского комплекта и `data/processed/far_east/`. Объединение этих материалов с целевыми рядами ML не выполняется автоматически.

## Открыть результат

Основная папка: `data/processed/freight_packages/`.

| Край | Региональная грузовая статистика | Ввоз: записи отправок/публикаций | Вывоз: записи отправок/публикаций |
|---|---|---|---|
| Камчатский | [statistics.csv](../data/processed/freight_packages/regions/kamchatka/statistics.csv) | [inbound.csv](../data/processed/freight_packages/regions/kamchatka/inbound.csv) | [outbound.csv](../data/processed/freight_packages/regions/kamchatka/outbound.csv) |
| Приморский | [statistics.csv](../data/processed/freight_packages/regions/primorye/statistics.csv) | [inbound.csv](../data/processed/freight_packages/regions/primorye/inbound.csv) | [outbound.csv](../data/processed/freight_packages/regions/primorye/outbound.csv) |

Общие файлы: [region_statistics.csv](../data/processed/freight_packages/region_statistics.csv), [od_freight.csv](../data/processed/freight_packages/od_freight.csv). Региональные файлы — их подвыборки, не дополнительные наблюдения.

[table_catalog.csv](../data/processed/freight_packages/table_catalog.csv) содержит полный перечень CSV и преобразованных листов; [quality_report.md](../data/processed/freight_packages/quality_report.md) — фактическое число строк, ограничения и результаты обработки. Папки `tables/<package_id>/` содержат все предоставленные CSV: погоду, тарифы, пассажирский багаж, живых животных, транзит, параметры услуг и инфраструктуры, подтверждения маршрутов и таблицы исходных проверок. Пустые таблицы сохраняют заголовок.

`excel/` — значения всех непустых листов XLSX с исходными строками и позициями столбцов. Эти технические выгрузки могут содержать общероссийскую таблицу аэропортов: наличие строки в таком CSV не присваивает ей Камчатку или Приморье. `compressed_csv/` — только строки двух краёв из широких CSV.GZ; все исходные годовые колонки сохранены, включая пустые и исторические.

`missing_values.csv` показывает пустые поля каждого исходного CSV. Не каждое пустое поле является потерянным наблюдением: `value_tonnes` неприменимо к TEU и контейнерам, а отсутствие точных границ отчётного периода не исправляется датой публикации.

Пройдены 54 проверки выбранных модулей ETL, включая восемь новых тестов обработчика.

Архивы и все их вложения сохранены неизменными в `data/raw/freight_packages/<package_id>/<SHA-256 архива[:16]>/`; сам ZIP называется `package.zip`. [archive_inventory.csv](../data/processed/freight_packages/archive_inventory.csv) содержит точный путь и SHA-256 каждого файла. Совпадения байтов между архивами отмечены, не считаются новыми данными.

[source_registry.csv](../data/processed/freight_packages/source_registry.csv) связывает глобальный `source_id` с исходным ID, организацией, URL, периодом, единицей, правами, ограничениями и локальным первоисточником. Снимки HTML/PDF сохранены как доказательства; они не объявляются числовыми CSV. Скрипты из пользовательских архивов не запускаются. Опубликованные числа в предоставленных CSV не извлекаются заново из каждого PDF/HTML и требуют предметной проверки.

## Что изменено при очистке

- Проверены полный состав ZIP, размеры и SHA-256 всех вложений по внутренним манифестам, а также хеши первоисточников из реестров.
- Убраны внешние пробелы, числа в известных числовых полях записаны с десятичной точкой; коды, исходные значения и категории сохранены. Нули и пропуски различаются, отсутствующие значения не заполняются.
- У `source_id`, `record_id`, `series_id` появилось пространство имён пакета: одинаковые короткие ID из разных архивов не сталкиваются. Прежние ID остаются в `provided_*`.
- Проверен перевод массы из явно указанных единиц; результат находится в `calculated_value_tonnes`, сверка — в `mass_conversion_check`. Конфликт не исправляется догадкой: сохраняются оба числа и флаг. Контейнеры, TEU, машины и головы животных не превращаются в тонны.
- Год, месяц и накопление с января получили разные обозначения. Дата публикации не подменяет период перевозки, исторические значения не распределяются по месяцам.
- Точные повторы внутри исходного CSV исключаются с записью в [row_issues.csv](../data/processed/freight_packages/row_issues.csv); конфликтующие ключи сохраняются с флагом. Преобразования числовых записей также отражены в журнале.
- Метки `verified` из архивов сохранены как `provided_review_status`. Статус нашей предметной приёмки — `pending`; происхождение — `provided_unverified`. Исходный статус наблюдения или оценки не заменяется.

**Один физический поток может присутствовать в двух пакетах:** например, как вывоз из Камчатки и ввоз в Приморье. [flow_links.csv](../data/processed/freight_packages/flow_links.csv) отмечает такие кандидаты на пересечение. Автоматического сложения и удаления этих записей нет. Также нельзя складывать итоги и подгруппы, разные единицы и этапы движения одной партии.

## Повторить обработку

Из корня проекта, Python 3.11+; дополнительных зависимостей не требуется:

```bash
python -m pipeline.freight_packages --input-dir .
python -m pipeline.freight_packages --verify
python -m pipeline.freight_packages --package
```

Первый запуск читает архивы из указанной папки. При повторении используются те же оригиналы; результат зависит от их SHA-256 и кода. Без исходных файлов вводной папки достаточно собрать их из сохранённых `package.zip` по полю `filename` в `manifest.json`. При передаче ZIP содержит оригиналы, результаты и код; первоначальное расположение архивов в корне не является обязательным.

Команда `--verify` проверяет сохранность, происхождение и пересчёт единиц. Команда `--package` сохраняет локальный ZIP и SHA-256 в `reports/generated/`; внешней отправки нет. Старые таблицы, реестр и модели проектного конвейера не переписываются. Сами ZIP и обработанные данные исключены из Git; код и эта инструкция доступны для коммита отдельно.

Проверки на вымышленных данных: `python -m unittest discover -s tests -p test_freight_packages.py -v`. Проверяются повреждение манифеста, небезопасный путь, различие нуля и пропуска, специальные коды, несовместимые единицы, отрицательная масса, конфликт ключа, пересечение региональных представлений и воспроизводимость.

ИИ помог написать импорт, очистку, проверки и инструкцию. Человек должен подтвердить первичные числа, территорию и направление, охват показателей, повторы физических отправок и историческую доступность факторов. Выбор цели ML и объединение временных рядов остаются решениями команды.
