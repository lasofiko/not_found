# Запуск ML и материалы для жюри

Нужны Python 3.11+, код и локальные данные/артефакты. В дереве проекта доступны
[карточки и метрики для жюри](jury/README.md); исходные ряды, модели и полные
прогнозы исключены из Git. **Подробная ручная сверка ячеек проведена Петей
частично**; конкретный охват не указан. Это отдельно от автоматической проверки.

## Подготовленный комплект

Используйте код и данные одной версии из архива передачи; не заменяйте его
`pipeline/` или `ml/` произвольной копией из другой ветки. Проверьте SHA-256 ZIP
по соседнему файлу `.sha256`, распакуйте в отдельную папку и работайте из неё.
В PowerShell: `Get-FileHash FILE.zip -Algorithm SHA256`; на Linux:
`sha256sum -c FILE.zip.sha256`. Само клонирование не создаёт данные и модели.

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,data,ml]"
python -m pipeline.verify
```

PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,data,ml]"
python -m pipeline.verify
```

Для двух распакованных частей под текущий код:

```bash
python -m pipeline.team_bundle --from-processed not_found-data-bundle-2026-11-10-part1-processed --raw-root not_found-data-bundle-2026-11-10-part2-raw --prepare
python -m pipeline.verify
```

После изменения документов/кода из отпечатка сборки повторите сборку тем же
конвейером. Манифест вручную не редактируется. Различие версии из-за документации
не разрешает использовать модель, обученную на других наблюдениях.

## Сохранённые результаты и расчёт действий

Для актуального сценарного пересчёта достаточно сохранённого годового артефакта
`models/latest.json`, CSV набора и календаря `ml/inputs/ferry_repairs.csv`:

```bash
python -m ml.hypotheses
```

Команда выводит новую папку `reports/generated/ml-hypotheses/<версия>/`:

| Файл | Содержание |
|---|---|
| `hypotheses-report.md` | Объяснение допущений и таблица 2027 |
| `hypothesis_results.csv` | Косвенные оценки и сценарные результаты гипотез |
| `action_scenarios.csv` | Оба направления и годы: база, А, Б и сочетание |
| `ferry_month_panel.csv`, `fleet_regression.csv` | Исследовательская панель и регрессия |
| `run_manifest.json` | Версии и хеши результатов |

Если годового артефакта нет, он создаётся отдельно:

```bash
python -m ml.run --end-year 2030
python -m ml.hypotheses
```

Годовая модель — только линия Усть-Луга — Балтийск, история 2015–2023,
по девять точек на направление. WAPE временной проверки 2022–2023 берётся
из выбранного артефакта и публикуется в `docs/jury/metrics.csv` и карточке линии.
Это шаг один год, не доказанная точность до 2030.
Выходы: `reports/generated/ml/<версия>/`, JSON модели — `models/<версия>/`.

## Месячные модели

Основная цель — грузы на паромах порта Калининград, вторая — контейнеры;
общий итог справочный. Единица — тонны за месяц, статус цели estimated.
Петропавловск-Камчатский и Владивосток проверяют перенос процедуры.
Направления и OD портового каботажа не выделяются.

Для **нового разрешённого эксперимента** после фиксации кода и протокола:

```bash
python -m ml.port_run --all-targets
# Либо отдельная цель:
python -m ml.port_run --target kaliningrad_ferries
```

Окно выбора: июль 2024 — июнь 2025; проверка: июль — декабрь 2025.
`metrics.json`, `backtest.csv`, `model-card.md`, графики и прогнозы находятся
в `reports/generated/ml-port/<версия>/`. Указатели — `models/port/<target>/latest.json`.
Интервалы 80/95% условные; продолжение до 2030 экспериментально.

Для зафиксированного протокола 10.11.2026 **пять проверок уже завершены**.
Не запускайте их повторно при подготовке сдачи. Команда ниже документирует
первоначальную процедуру и требует отдельного разрешения для нового протокола:

```bash
# Однократно, после просмотра обычных метрик и фиксации метода:
python -m ml.port_run --all-targets --blind-check
```

Блокировки: `reports/generated/ml-port/blind_checks/`. Их нельзя удалять ради
нового выбора. Открываются только нужные накопления 2026; они не добавляются
в обучение. Для жюри используются сохранённые результаты: ошибки и сравнение
с naive вычисляются из проверенной пары артефактов. Ошибка суммы восьми месяцев
показывается отдельно от сентябрьской, не является пределом ошибки месяца.

## Карточки и метрики вне локальных отчётов

Подставьте папку, напечатанную `ml.hypotheses`:

```bash
python -m ml.export_jury --hypotheses-dir reports/generated/ml-hypotheses/ВЕРСИЯ
```

Экспорт создаёт `docs/jury/README.md`, шесть карточек, `metrics.csv`,
`blind-metrics.csv`, `scenarios.md` и `evidence.json`. Проверяются SHA-256
моделей, завершение блокировок, соответствие выбранной модели, версии данных,
протокола и обучающей серии, совпадение годовых наблюдений с артефактом.
Для прежней схемы необходим исходный замороженный манифест запуска с хешами
`training_series.csv` и `blind_check.json`. Если этих доказательств нет или
указатель выбрал другую модель, экспорт завершается ошибкой до записи документов.
Восстановите согласованный исходный комплект; повторное открытие 2026
или удаление блокировки для исправления экспорта не требуется.
Обучения и повторной проверки 2026 нет. Исходные ряды, прогнозы и состояния
моделей в этот комплект не копируются. Права на публикацию рядов SeaNews
не подтверждены. Документы доступны в дереве репозитория; внешняя публикация
и отправка жюри выполняются отдельно.

## Функции для последующей интеграции

```python
from ml.predict import forecast
from ml.port_predict import forecast_port

line = forecast(direction="inbound", end_year=2030)
port = forecast_port(end_period="2026-12", target_id="kaliningrad_ferries")
```

Функции возвращают статус, единицу, периоды, интервалы, версии, происхождение
и предупреждения. Без сохранённых артефактов они отклоняются. Backend/frontend
в этой работе не подключались, основной интерфейс пока показывает синтетические
примеры. Будущая интеграция следует `docs/api_contract.md`.

## Проверки

```bash
python -m pipeline.verify
python -m pipeline.reproduce
python -m pytest -q
```

Тесты используют синтетические примеры и не являются оценкой точности реальных
рядов. «SHA-256 не совпадает» требует согласованного комплекта или пересборки,
а не исправления хешей руками. Незавершённая слепая проверка требует разбора сбоя.
ИИ помогает с кодом и техническими проверками; человеческая сверка учитывается
отдельно в `data/review-status.json` и журнале конкретных проверок.
