# Как подготовить свой CSV наблюдений

Шаблон: [observations-template.csv](../data/examples/observations-template.csv). Он содержит только заголовок: вымышленных перевозок в нём нет. Скопируйте его, добавьте строки и сохраните как UTF-8 CSV с разделителем запятая. В Excel проверьте разделитель и десятичную точку. Запятая внутри исходного числа допустима только в заключённой в кавычки ячейке CSV.

Проверка из корня проекта или переданного комплекта, Python 3.11+, без сети и дополнительных пакетов:

```bash
python3 -m pipeline.input_check /путь/свой.csv
python3 -m pipeline.input_check /путь/свой.csv --observed-only
```

Проверка не загружает данные в модель и не утверждает новую цель. После добавления реальных наблюдений нужны предметная приёмка, воспроизводимая подготовка и переобучение. Значения мощности, тарифов, прогнозов и сценарной потребности не включаются в этот файл.

## Поля

| Поле | Правило |
|---|---|
| `period` | Год `2023` либо месяц `2023-01`; дата начала/конца и произвольный текст не принимаются |
| `period_granularity` | `year` или `month`; годовой факт нельзя повторить двенадцать раз как месячный |
| `origin`, `destination` | Коды территорий/портов, а не адреса. Калининград: `kaliningrad_oblast`, `kaliningrad_port`; основная часть РФ: `mainland_russia`, `ust_luga`, `saint_petersburg`. Новый код требует обновления словаря и проверки географии |
| `direction` | `inbound`: из основной части РФ в область; `outbound`: обратно. Итог двух направлений в эту схему не помещается |
| `mode` | `sea`, `rail_land`, `road`, `air`; вагон на пароме — `sea` |
| `cargo_group` | Название группы из согласованного классификатора; агрегат «все грузы» хранить отдельно от вложенных групп, не суммировать с ними |
| `value_tonnes` | Конечное неотрицательное число в тоннах, десятичная точка, без пробелов; пустая ячейка — пропуск, `0` — реальный опубликованный ноль |
| `status` | `observed`: опубликованное наблюдение; `estimated`: расчёт с формулой; `synthetic`: тестовая запись, в реальной обучающей цели запрещена. `forecast`/`scenario` отклоняются |
| `source_id` | Существующий паспорт в `data/source_registry.json`; его оригинал должен присутствовать и совпадать по SHA-256. Проверяются используемые источники; отсутствие посторонних оригиналов не блокирует этот CSV |
| `source_locator` | Обязательно конкретное место: годовая вкладка + строка/ячейка, либо лист + адрес, либо PDF-страница + подпись. Один URL без места недостаточен для сверки человеком |
| `original_value` | Точное число или прочерк из источника. Пробелы и десятичная запятая допускаются здесь. Для вычисленного числа — результат формулы в единице `original_unit`, со ссылками на слагаемые в `formula` |
| `original_unit`, `conversion_factor` | Только `тонн` → `1`, `тыс. тонн` → `1000`, `млн тонн` → `1000000`. `value_tonnes = original_value × conversion_factor` |
| `route_id` | Код линии/маршрута, если известен; для данного кандидата `ust_luga_kaliningrad_ferry`. Разные названия одного маршрута нужно согласовать, чтобы не скрыть дубль |
| `in_wagon_on_ferry` | `true`/`false`/пусто. `true` допустимо только для `sea`; пусто — неизвестно или смешанный агрегат, а не `false` |
| `quality_note` | Оговорки: охват, тара, версия, предварительность, причина пропуска |
| `data_version` | Версия воспроизводимого набора, когда она присвоена; не заменяет хеш оригинала |
| `formula` | Обязательна для `estimated`: вычисление и местонахождение всех исходных величин; для прямого наблюдения пусто |
| `shipment_id` | Необязательный устойчивый обезличенный идентификатор физической отправки. Повтор запрещён, даже для другого вида/периода; иной участок не является второй массой коридора |

Первые десять полей и четыре поля происхождения обязательны в заголовке. В заполненной строке обязательно место в оригинале, единица и коэффициент. Дополнительные поля рекомендуется сохранять из шаблона.

## Примеры ошибок

| Ввод | Результат |
|---|---|
| `2026-13`, `period_granularity=month` | Невозможный календарный месяц |
| `origin=kaliningrad_port,destination=ust_luga,direction=inbound` | Направление противоречит OD |
| `original_value=1,original_unit=тыс. тонн,conversion_factor=1000,value_tonnes=1` | Неверный пересчёт; должно быть 1000 тонн |
| `original_value=–,value_tonnes=0` | Пропуск подменён нулём |
| `original_unit=TEU`, `вагоны`, `автомобили`, `т·км` | Несовместимая величина; универсального перевода в тонны нет |
| `original_value=CD/ND/-77777777/-99999999` | Требуется паспорт кода и отдельная подготовка; отрицательная масса и автоматический ноль запрещены |
| Одинаковые период × OD × направление × вид × группа × маршрут из двух источников | Повтор/конфликт; автоматического сложения или выбора версии нет |
| `in_wagon_on_ferry=true,mode=rail_land` | Двойной учёт морского вагона как сухопутного пересечения запрещён |
| Один `shipment_id` в двух строках | Одна отправка учтена повторно |
| `estimated` без `formula` | Нет воспроизводимого расчёта |

Без идентификаторов отправок программная проверка не докажет отсутствие одного физического груза в независимых агрегатах. Проверяющий должен подтвердить определение массы и границы учёта. Портовая перевалка, региональные итоги и пересечения автомобилей не становятся целевой массой из-за корректного заголовка CSV.

## Человеческая сверка и принятие

В [human-review-log.csv](../data/human-review-log.csv) реальный проверяющий заполняет по строке на каждую сверенную ячейку: имя, дату ISO, `source_id`, полный SHA-256, точный `source_locator`, результат `matched`/`issue`/`unresolved`, замечание. Локаторы и хеши удобно брать из `data/processed/target-source-check.csv`. Это не означает, что нужно подтвердить все строки: сомнение фиксируется как `issue` или `unresolved`.

Пока журнал пуст, человеческая проверка не выполнена. Совпадение чисел не решает вопросы тары, операторов и расхождений терминала; их отражают в решении команды. После заполнения выполните пересборку: хеш журнала включается в версию набора. Данные остаются кандидатными до отдельного утверждения. Автоматическая сборка не создаёт окончательный `observations.csv` и не изменяет уже существующий файл команды.
