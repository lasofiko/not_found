# Балтийский баланс — 2030

Инструмент исследования грузов **между Калининградской областью и основной частью РФ** и транспортных сценариев. История, прогноз и сценарная потребность показываются отдельно. Добавлена экспериментальная ML-демонстрация конкретной паромной линии по двум направлениям; подтверждённого полного целевого ряда всего коридора пока нет.

## ML-прогноз: оба направления паромной линии

На Linux/macOS из корня проекта, с подготовленным локальным комплектом (Python 3.11+):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[ml]"
python -m ml.run --end-year 2030
```

Если `.venv` уже существует, повторно создавать его не нужно. В новом терминале сначала выполните `source .venv/bin/activate`; без активации используйте `.venv/bin/python` вместо `python`. На Windows PowerShell активация: `.\.venv\Scripts\Activate.ps1`.

Три метода (`naive`, `drift`, `ses`), выбор по 2020–2021, отдельная проверка 2022–2023, итоговое обучение на 2015–2023. Прогноз 2024–2030 и модельные интервалы сохраняются в `reports/generated/ml/<версия>/`, переносимый JSON модели — в `models/<версия>/`. Оба каталога вне Git. Последний факт — 2023; прогноз не описывает весь коридор и не доказывает точность до 2030.

Функция для Fullstack: `from ml import forecast; forecast(direction="inbound", end_year=2030)`; для обратного направления — `outbound`. Сам HTTP endpoint прогноза ещё не подключён. Полная инструкция, протокол и проверки: [ML README](ml/README.md). Код и контракт v0.6 — в ветке `ml/ferry-forecast`.

Интерактивный отчёт о влиянии параметров: `python -m ml.sensitivity`. Команда напечатает путь к автономному `report.html`: откройте его браузером. Выбор направления/года и три регулятора показывают изменение дефицита и запаса провозной возможности. Нагрузка, исходная возможность и её прибавка — сценарные допущения в процентах от базового прогноза; это не измеренная мощность или обученное влияние факторов. Расчёты, сравнение примеров и CSV/JSON сохраняются отдельно в `reports/generated/sensitivity/`. Для отчёта достаточно уже сохранённой модели; переобучение не требуется.

## Быстрый запуск

Нужен Python 3.11+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
uvicorn backend.app:app --reload
```

Откройте `http://127.0.0.1:8000`. API: `http://127.0.0.1:8000/docs`. Главная страница позволяет проверить расчёт дефицита мощности на **введённых пользователем** значениях. Эти значения не являются прогнозом модели.

Проверка таблицы наблюдений: `python -m pipeline.validate data/processed/observations.csv`. Пока файла нет, команда сообщит об этом: исходные данные не скопированы в репозиторий автоматически.

## Подготовка данных

Реестр оригиналов: [data/source_registry.json](data/source_registry.json). Каталог из Google-таблицы: [data/source_catalog.csv](data/source_catalog.csv). Исследуется **весь грузовой коридор по четырём видам транспорта**. Полного сопоставимого целевого ряда пока нет.

Для присланных файлов в `data/incoming/` (экспортные XLSX, транзитный XLS, объединённый Excel и два ZIP), с активным Python 3.11+ окружением:

```bash
python -m pip install -e ".[data,notebooks]"
python -m pipeline.acquire --local-dir data/incoming
python -m pipeline.build --available-only
python -m pipeline.verify
python -m jupyterlab notebooks/dataset_overview.ipynb
```

После установки зависимостей этот путь работает офлайн. Внутренние манифесты ZIP и SHA-256 проверяются; одинаковые вложения не размножаются. `--available-only` перечисляет отсутствующие источники в манифесте; порча существующего оригинала останавливает сборку. Повторный импорт восстанавливает файлы без дублирования паспортов. Исходники с читаемыми именами находятся в `data/incoming/`; рабочие неизменяемые копии — в `data/raw/`. Обе папки исключены из Git. В распакованном архиве передачи с заполненным `data/raw/` повторный импорт не требуется.

Результаты: [грузовой срез региона](data/processed/regional_freight.csv), [частичные транспортные показатели](data/processed/supplemental_freight.csv), [портовый каботаж с января](data/processed/port_cabotage_cumulative.csv), [оценки месячных разностей](data/processed/port_cabotage_monthly.csv), [пересечения грузовиков](data/processed/border_crossings.csv), [карта покрытия](data/processed/freight_coverage.csv). Полный региональный набор — `regional_indicators.csv`, диагностика — `supplemental_issues.csv`; реальные CSV остаются вне Git. [Качество и ограничения](docs/supplemental-quality.md), [что вам сделать сейчас](docs/data-engineer-next-steps.md).

Первоисточник Росморпорта получен: `candidate_observations.csv` содержит **18 годовых строк за 2015–2023**, по девять на направление узкой паромной линии. Все 18 значений автоматически сверены с предоставленным CSV из ZIP — совпадают. `context_observations.csv` содержит 18 строк терминальных итогов/каботажа, `coverage.csv` — четыре ряда покрытия. Человеческая проверка методики и выбор цели остаются открытыми.

На другой машине для заполнения кандидата нужны сохранённые оригиналы из архива передачи либо получение страницы: `python -m pipeline.acquire --source rosmorport_freight`, затем `python -m pipeline.build --available-only`. При отсутствии страницы этот файл содержит только заголовок; копия из ZIP остаётся отдельно в `supplemental_freight.csv`.

Строгое воспроизведение по **всем зарегистрированным оригиналам**, если они переданы:

```bash
python -m pipeline.acquire
python -m pipeline.build
python -m pipeline.verify
python -m pipeline.validate data/processed/candidate_observations.csv --registry data/source_registry.json --corridor --require-observations --observed-only
python -m unittest discover -s tests -v
python -m pipeline.package
```

`acquire` нужен только для получения отсутствующих оригиналов (интернет); сохранённые оригиналы проверяются по хешу. Если дополнительный источник недоступен, команда возвращает ошибку, сохраняя успешно полученные файлы; обязательные для сборки источники перечислены в инструкции. По переданным оригиналам `build` и `verify` работают **офлайн**. Для старого XLS нужен `xlrd==2.0.2`: в комплект уже включён официальный wheel с проверяемым SHA-256; при отдельной установке используйте `pip install -e ".[data]"`. Остальные таблицы читаются стандартной библиотекой. Существующий `observations.csv` не перезаписывается. Справочные показатели, параметры объектов и факторы хранятся отдельно. Локальный ZIP передачи создаётся в игнорируемой Git папке `reports/generated`, без внешней публикации.

Покрытие, варианты цели, ошибки источников и участие ИИ: [аудит](docs/data-audit.md). Полная инструкция, правила очистки и приёмка человеком: [подготовка и передача](docs/data-preparation.md).

В экспортных файлах **только январь 2021 и январь 2022**, а виды экспорта вложены друг в друга. Это внешняя торговля регионов, без подтверждённого соответствия перевозкам нужного коридора. Транзитный XLS содержит выборку товарной группы 2204 (вино); принадлежность Калининградскому коридору не установлена. Эти таблицы сохраняются отдельно от кандидата целевого ряда.

Обработка сохраняет пропуски, переводит кг в тонны и тыс. USD в USD, проверяет ключи, даты и индексы роста. Из очищенного транзита исключены реквизиты участников и транспорта; товары связываются хешем декларации. Оригинал с этими реквизитами остаётся локальным и включается в ZIP, который следует передавать согласованным получателям. Ссылка на публикацию и методика четырёх файлов пока не установлены.

Повторная обработка текущего комплекта: `python -m pipeline.build --available-only`, затем `python -m pipeline.verify`. Как импортировать такие файлы на другой машине: [инструкция](docs/data-preparation.md#импорт-пользовательских-таблиц).

## Структура

| Каталог | Назначение |
|---|---|
| `docs/` | Архитектура, договорённости и контракты |
| `data/raw/` | Неизменённые первоисточники, локально |
| `data/interim/` | Промежуточные преобразования, локально |
| `data/processed/` | Проверенные таблицы для модели, локально |
| `data/examples/` | Малые примеры схем без вымышленных целевых фактов |
| `pipeline/` | Проверка и последующая сборка наборов |
| `ml/` | Контракт модели и будущие baseline/backtesting |
| `backend/` | API и расчёт сценария |
| `frontend/` | Статическая страница без отдельной сборки |

Исходный `main.py` оставлен без изменений. Материалы кейса находятся в отдельной папке `кейс чемпионат/outputs`; их нужно подключать через реестр источников, а не переносить все файлы в Git.

Предложения к обсуждению цели, проверки прогноза и логистической цепочки: [вопросы команды](docs/team-discussion.md).

## Следующие решения команды

1. Выбрать проверяемый целевой ряд и его частоту; подтвердить, можно ли получить месячные тонны по нужной паре регионов.
2. Утвердить две гипотезы действий и подтверждённые диапазоны мощности, сроков, CAPEX/OPEX.
3. Выбрать модели и временные срезы проверки; решить охват логистической цепочки.
4. Зафиксировать обязательный объём интерфейса к сдаче и горизонт (2030 или гибкий до 2035).
