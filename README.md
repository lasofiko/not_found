# FloCast

## Отдельный синтетический эксперимент

`python -m pipeline.synthetic --input "new data" --output reports/generated/flocast-synthetic-new`
последовательно инвентаризирует снимок, исследует ряды, фиксирует план, выполняет
генерацию, временную проверку и отдельный опыт дополнения обучающих данных.
Рабочие модели и реальные таблицы не меняются. Для запуска нужны существующие
зависимости `[ml,data]`; локальные CSV, оригиналы и ZIP сохраняются вне Git.
Результаты 12-месячного опыта имеют статус synthetic, месячные исходные разности —
estimated. Оптимистичный и стрессовый сценарии требуют явных численных допущений.
Проверка комплекта: `python -m pipeline.synthetic --verify DIRECTORY`.
Read-only API `/api/v1/synthetic/*` включается через `BB_SYNTHETIC_PATH`.
[Методика, файлы и интеграция](docs/synthetic-generation.md).

## Единый актуальный архив данных

`python -m pipeline.current_snapshot` создаёт локальный снимок доступных данных,
дополнений, оригиналов, сохранённых моделей/результатов и пояснений в
`reports/generated/current-data-2026-11-12-<version>/`.
При превышении 400 МБ файлы распределяются между самостоятельными ZIP до
400 000 000 байт каждый. Все части распаковываются в один пустой каталог.
Каталог, ограничения и SHA-256 входят в комплект; проверка без извлечения:
`python -m pipeline.current_snapshot --verify DIRECTORY`.
Снимок не пересобирает таблицы и не меняет их статус проверки. Старые архивы
передачи, повторные CSV из `data/ml_handoff`, окружение и секреты исключаются.
Новый рабочий раздел **«Сравнить решения»** (`/#compare`) объединяет сравнение
базы/резерва/дополнительного парома, пороги, паспорта показателей, профиль ввоза
и вывоза, матрицу покрытия, обоснование HTML/CSV/JSON и пояснение применённого
снимка в существующей AI-панели. Основные расчёты работают без LLM; прямой ввод —
также без модели. [Пользовательский путь и ограничения](docs/decision-workspace.md).
Снимки действуют 30 минут; приложение запускается с одним worker.
Реализация, файлы, фактические проверки и средовые ограничения:
[итоговый отчёт](docs/decision-implementation-report.md).
После запуска: `python scripts/smoke_decisions.py`; флаг `--expect-llm-disabled`
проверяет режим без провайдера и не вызывает платную модель.

## Контейнерный запуск и интеграция main/devops

Из корня репозитория, с Docker Desktop в режиме Linux containers (Compose 2.24+):

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
docker compose up --build
```

Сайт: **http://127.0.0.1:8000/**, Swagger: **http://127.0.0.1:8000/docs**.
Один контейнер собирает утверждённый React и запускает FastAPI, который отдаёт
тот же интерфейс. Модели подключаются из `BB_MODELS_PATH` (по умолчанию `./models`)
только для чтения; без них API и сценарный калькулятор работают, прогноз явно недоступен.
LLM необязателен: нужны `BB_LLM_BASE_URL`, `BB_LLM_API_KEY`, `BB_LLM_MODEL`.
Никакого обучения или подмены данных при старте нет.

```powershell
docker compose up --build --detach --wait --wait-timeout 120
docker compose ps
docker compose logs --tail 100 --follow
docker compose down
```

Закреплённые Python-зависимости для разработки (установите `uv==0.13.7`):

```powershell
uv sync --locked --extra dev --extra data --extra ml
npm --prefix frontend ci
npm --prefix frontend run build
uv run --locked --no-sync uvicorn backend.app:app --reload
```

Если существующая `.venv` создана другой версией Python или содержит несовместимые
бинарные пакеты, сохраните её и создайте отдельное окружение из того же lock-файла:

```powershell
$env:UV_PROJECT_ENVIRONMENT = '.cache/venv311'
uv sync --locked --python 3.11 --extra dev --extra data --extra ml
uv run --locked --no-sync python -c "import numpy, statsmodels.api, backend.app"
```

Эту переменную задавайте в каждом новом терминале. В текущей рабочей копии
проверенное окружение находится в `.cache/venv311`; прежняя `.venv` сохранена.
Бинарные зависимости между версиями Python не копируются.

Для разработки React во втором терминале: `npm --prefix frontend run dev`.
Проверки: `uv run --locked --no-sync pytest -q`,
`uv run --locked --no-sync ruff check backend scripts/smoke.py`,
`npm --prefix frontend run lint`, `npm --prefix frontend test`,
`npm --prefix frontend run build`. После запуска сервера:
`uv run --locked --no-sync python scripts/smoke.py`.

Подробные команды для PowerShell/Linux, карта переменных, ML, диагностика Docker/LLM,
ограничения CI и production: [инструкция DevOps](docs/devops.md).
Фактические результаты интеграции: [отчёт](docs/devops-integration-report.md).

Исправления для демонстрации от 12.11.2026, таблица всех 20 пунктов, проверки
и оставшаяся приёмка: [отчёт готовности](docs/hackathon-readiness-2026-11-12.md).
Подготовка данных/моделей допускает одного писателя на рабочую копию;
повторяйте команду после завершения другой. Не удаляйте файл блокировки:
блокировку автоматически освобождает ОС. Замороженные исследования и blind
не нужно пересчитывать для запуска сайта.

FloCast — исследовательский прототип команды **Not Found** для анализа грузовых перевозок между Калининградской областью, Приморским краем, Камчатским краем и остальной Россией. Наблюдения, ML-прогнозы, синтетические примеры и сценарные расчёты показываются отдельно.

**Единственный основной интерфейс — существующее React-приложение в frontend/.** Светлая серо-сиреневая тема, Sidebar, Hero с контейнеровозом, фиолетовые акценты, «Система в цифрах», карта и AI-панель сохранены. Доступно переключение светлой и тёмной тем.

## Что работает и какие есть ограничения

| Возможность | Текущее состояние |
|---|---|
| Единый интерфейс | Vite и FastAPI открывают одно React-приложение с утверждённым дизайном. |
| Годовой ML-прогноз | Подключён к API и React при наличии проверенного артефакта. Морская линия Усть-Луга — Балтийск, inbound/outbound, история 2015–2023, прогноз 2024–2030 в тоннах за год. Это не весь грузовой коридор; точность до 2030 не подтверждена. |
| Графики и экспорт | Графики, таблица и CSV прогноза используют один ответ API с источниками и версиями. При ошибке модели синтетические значения не подставляются. |
| Сценарный калькулятор | Встроен в React. FastAPI считает исходный и новый дефицит, изменение мощности, сокращение дефицита и запас по вводу пользователя. Это чувствительность, а не ML-прогноз или подтверждённый эффект инвестиции. |
| География и транспорт | Сохранены три региона, выбор направления и городов, карта OpenStreetMap и четыре транспортные фотокарточки. Наличие пункта выбора не означает наличие прогноза для него. Для карты нужен интернет. |
| Неподключённые срезы | Прогнозы Приморья, Камчатки, городской детализации, rail_land/road/air к HTTP API пока не подключены. Данные другого коридора не подставляются. |
| Синтетические примеры | Сохранены в отдельной аналитике и явно помечены synthetic; не являются наблюдениями или результатами модели. |
| AI-ассистент | Панель подключена к серверному API. Для ответов нужен настроенный OpenAI-compatible провайдер. Без него показывается LLM_NOT_CONFIGURED; остальные функции продолжают работать. Ключ остаётся на сервере. |

HTTP API запускается независимо от наличия ML-артефактов. Модель не обучается при HTTP-запросе. Эксперименты месячного каботажа остаются отдельным исследовательским контуром: [интеграция ML](docs/ml-integration.md), [ML README](ml/README.md).

## Архитектура и адреса

Точка входа: frontend/index.html → frontend/src/main.tsx → frontend/src/App.tsx. React обращается к FastAPI, а Backend — к существующим ML-модулям и данным. Вычисления калькулятора остаются в backend/scenarios.py.

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:8000/ | Основной адрес: FastAPI непосредственно отдаёт production-сборку React. |
| http://127.0.0.1:5173/ | То же приложение через Vite для разработки. |
| http://127.0.0.1:8000/#capacity | Калькулятор внутри основного интерфейса. |
| http://127.0.0.1:8000/docs | Swagger: действующие API и схемы. |
| /dashboard/ | Старая ссылка; перенаправляет на корень. |
| /capacity и /capacity.html | Старые ссылки; перенаправляют в /#capacity. |

Раньше FastAPI отдавал отдельный capacity.html на главной, а React размещался на /dashboard/. Теперь старые capacity.html/app.js сохранены как исходная реализация, но не образуют отдельный пользовательский интерфейс. SPA fallback зарегистрирован после API и не подменяет неизвестные API-маршруты или отсутствующие ресурсы HTML-страницей.

## Быстрый запуск

Нужны **Python 3.11** для проверенного lock-окружения, **Node.js 22.12+ из ветки 22 либо Node.js 24+** и npm. Далее все команды выполняются **из корня not_found**, если явно не указано иное.

### 1. Первичная установка

Windows PowerShell:

~~~powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
npm --prefix frontend ci
~~~

macOS и Linux:

~~~bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
test -e .env || cp .env.example .env
npm --prefix frontend ci
~~~

Если окружение и зависимости уже установлены, повторная установка не требуется. В новом терминале активируйте существующее .venv. Артефакты модели и данные не создаются установкой зависимостей; их подготовка описана ниже.

### 2. Демонстрация: один основной адрес

В активном Python-окружении:

~~~powershell
npm --prefix frontend run build
python -m uvicorn backend.app:app --reload
~~~

Откройте **http://127.0.0.1:8000/**. Vite для этого режима не нужен. На главной будет утверждённый React с контейнеровозом; калькулятор, прогноз и ассистент доступны внутри него.

После изменения React выполните build заново. Backend обнаруживает новую сборку без перезапуска. Изменения Python требуют reload или перезапуска сервера. git pull сам по себе не пересобирает frontend/dist.

### 3. Разработка: Backend и Vite отдельно

Терминал 1, активное Python-окружение, корень проекта:

~~~powershell
python -m uvicorn backend.app:app --reload
~~~

Терминал 2, корень проекта:

~~~powershell
npm --prefix frontend run dev
~~~

Откройте **http://127.0.0.1:5173/**. Vite проксирует /config.json и фактический BB_API_PREFIX к Backend на http://127.0.0.1:8000. Адрес Backend можно изменить через BB_DEV_BACKEND_URL в корневом .env или окружении. После изменения этих настроек перезапустите Vite.

**Если терминал уже находится в frontend**, команды выполняются без --prefix frontend:

~~~powershell
npm ci
npm run dev
~~~

Добавление --prefix frontend из этой папки заставляет npm искать frontend/frontend/package.json. Не закрывайте терминалы серверов: после остановки Vite его адрес перестаёт работать. Для работы API в режиме разработки production-сборка не требуется; она нужна для отображения React через адрес Backend.

### Проверка актуальности сборки

При build создаётся frontend/dist/build-info.json с SHA-256 исходников, public, конфигурации и итогового index.html. Backend сверяет сборку с текущим frontend вне основного асинхронного потока; результат кэшируется на 0,5 секунды. Замена манифеста или HTML инвалидирует проверку сразу. Изменение исходников обнаруживается при следующей полной проверке после истечения кэша. Если dist отсутствует, устарел или не прошёл проверку, UI возвращает HTTP 503 с командой сборки; API остаётся доступным.

При запуске из репозитория сохраняйте src, public и конфигурацию рядом с dist: они нужны для проверки. HTML не включается в PWA precache. После обновления старой версии страницы можно выполнить Ctrl+Shift+R.

## Конфигурация и AI-ассистент

Backend читает корневой .env через pydantic-settings; префикс переменных — BB_. Примеры находятся в [.env.example](.env.example). Существующий .env не перезаписывайте.

| Настройка | Назначение |
|---|---|
| BB_APP_NAME, BB_ENVIRONMENT, BB_LOG_LEVEL | Название приложения, окружение и журналирование. |
| BB_API_PREFIX | Префикс API, по умолчанию /api/v1. |
| BB_CORS_ORIGINS | Разрешённые origin для прямых запросов к API с другого адреса. При штатном Vite proxy запросы идут через адрес frontend. |
| BB_DEV_BACKEND_URL | Адрес Backend для Vite proxy, по умолчанию http://127.0.0.1:8000. |
| BB_LLM_BASE_URL, BB_LLM_API_KEY, BB_LLM_MODEL | Серверные настройки OpenAI-compatible провайдера. |
| BB_LLM_TIMEOUT_SECONDS | Таймаут обращения к провайдеру. |
| BB_LLM_ACCESS_TOKEN, BB_LLM_ALLOW_REMOTE | Bearer-токен доступа и явное разрешение удалённого LLM-доступа. В production токен обязателен, в том числе за локальным reverse proxy. |
| BB_LLM_REQUESTS_PER_MINUTE, BB_LLM_MAX_CONCURRENT_REQUESTS | Общие лимиты процесса: 30 запросов/минуту и 2 параллельных по умолчанию. |
| BB_LLM_MAX_TOKENS, BB_LLM_MAX_ANSWER_CHARS | Максимум ответа провайдера: 800 токенов и 12 000 символов по умолчанию. |
| BB_LLM_SUMMARY_CACHE_TTL_SECONDS | Кэш одинаковых проверенных контекстов сводки: 60 секунд, максимум 32 записи; 0 отключает. |

React получает актуальный apiBase из GET /config.json. При изменении BB_API_PREFIX перезапустите Backend, а при разработке — также Vite. Ключ LLM в браузер не передаётся.

Если не задан хотя бы один из BB_LLM_BASE_URL, BB_LLM_API_KEY или BB_LLM_MODEL, эндпоинты ассистента возвращают HTTP 503 / LLM_NOT_CONFIGURED. Контекст строится через тот же ForecastService, что `/forecasts`: проверенный годовой прогноз линии, версии, источники и ограничения. JSON-примеры в backend/jsons не загружаются. Ответ — интерпретация прогноза, с отдельным статусом interpretation. Без модели — LLM_DATA_NOT_FOUND, при повреждении — LLM_CONTEXT_INVALID. Для другого региона или городской детализации — LLM_CONTEXT_NOT_AVAILABLE. Панель использует применённые географию и направление, горизонт до 2030; фактический охват линии показан отдельно. Подробнее: [настройка LLM](docs/llm.md).

## Основные API

Пути приведены для стандартного BB_API_PREFIX=/api/v1.

| Метод и путь | Назначение |
|---|---|
| GET /api/v1/health | Проверка процесса Backend. |
| GET /api/v1/status | Доступность годовой модели и возможностей API. |
| GET /api/v1/config | Доступные настройки, годы и частота. |
| GET /api/v1/forecasts?region=kaliningrad&direction=inbound&mode=sea&end_year=2030 | Годовой ML-прогноз; поддерживается также outbound. |
| GET /api/v1/scenarios | Реестр транспортных действий без неподтверждённых численных эффектов. |
| POST /api/v1/scenarios/capacity | Сценарный баланс мощности по пользовательскому вводу. |
| GET /api/v1/llm/summary | Сводка ассистента по серверному контексту. |
| POST /api/v1/llm/ask | Вопрос ассистенту. |

Проверка из PowerShell:

~~~powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
Invoke-RestMethod http://127.0.0.1:8000/api/v1/status
Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/forecasts?region=kaliningrad&direction=inbound&mode=sea&end_year=2030'
~~~

При корректном комплекте models модель имеет статус ready и forecast=true. Без артефакта прогноз сообщает not_connected; повреждённый комплект не заменяется фиктивным результатом. Калькулятор считает только чувствительность к введённым значениям, поэтому его доступность не означает готовности полного сценарного анализа: status.capabilities.scenario_analysis остаётся false.

Будущие /history, /scenarios/compare, /sources и /datasets/upload описаны в [контракте API](docs/api_contract.md), но пока не зарегистрированы. Точные схемы действующих маршрутов доступны в /docs.

## Если не запускается

| Симптом | Что проверить |
|---|---|
| npm ищет frontend/frontend/package.json или ci не видит lockfile | Выполняйте команды с --prefix frontend только из корня. Внутри frontend используйте npm ci и npm run dev. |
| Браузер не открывает 5173 | Терминал Vite должен оставаться запущенным. Используйте http://127.0.0.1:5173/; при ошибке запуска прочитайте вывод терминала. |
| Backend отвечает 503 на главной | Выполните npm --prefix frontend run build из корня и обновите страницу. |
| Vite показывает интерфейс, но API недоступно | Запустите Backend; проверьте /api/v1/health, BB_DEV_BACKEND_URL и совпадение BB_API_PREFIX. |
| Прогноз сообщает not_connected | Нужен проверенный комплект модели. См. [интеграцию ML](docs/ml-integration.md); вымышленные прогнозы не подставляются. |
| Ассистент сообщает LLM_NOT_CONFIGURED | Настройте серверные BB_LLM_* и перезапустите Backend. |
| Ассистент сообщает LLM_DATA_NOT_FOUND / LLM_CONTEXT_INVALID | Подключите проверенный комплект models / восстановите его целостность. Обучение при HTTP-запросе не выполняется. |
| Ассистент сообщает LLM_CONTEXT_NOT_AVAILABLE | Контекст подключён только для агрегированного выбора Калининграда, двух направлений и морской линии Усть-Луга — Балтийск. |

## Проверки

Из корня, в активном Python-окружении с зависимостями dev и установленными frontend-зависимостями:

~~~powershell
python -m pytest backend/tests -q
python -m ruff check backend
python -m ruff format --check backend
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
~~~

## Локальные ML-эксперименты

На Linux/macOS из корня проекта, с подготовленным локальным комплектом (Python 3.11+):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[ml]"
python -m pipeline.verify
python -m ml.run --end-year 2030
```

Если `.venv` уже существует, повторно создавать его не нужно. В новом терминале сначала выполните `source .venv/bin/activate`; без активации используйте `.venv/bin/python` вместо `python`. На Windows PowerShell активация: `.\.venv\Scripts\Activate.ps1`.

`ml.run` реализует годовой прогноз линии Усть-Луга — Калининград: по девять наблюдений 2015–2023 отдельно для `inbound` и `outbound`. Три метода (`naive`, `drift`, `ses`), выбор по 2020–2021, отдельная проверка 2022–2023, итоговое обучение на 2015–2023. При успешном запуске прогноз 2024–2030 и модельные интервалы сохраняются в `reports/generated/ml/<версия>/`, переносимый JSON модели — в `models/<версия>/`. Оба каталога вне Git. Последний факт — 2023; модель не описывает весь коридор и не доказывает точность до 2030.

Отдельные команды с тем же подготовленным комплектом и активным окружением:

```bash
python -m ml.port_run
python -m ml.line_experiment
```

`ml.port_run` следует [протоколу 10.11.2026](docs/ml-port-evaluation-protocol.md): основная цель — грузы на паромах порта Калининград, 43 месяца с июня 2022 по декабрь 2025, статус `estimated`. Кандидаты: naive, seasonal_naive, drift, ses; Ridge исключена из сравнения. `--target kaliningrad_containers` и `--target kaliningrad_total` выбирают другие группы; `--all-targets` запускает доступные цели и сообщает об отсутствующих. Во входном processed-комплекте ряды каботажа двух дальневосточных портов отсутствуют. Указатели разделены по `models/port/<target_id>/`, отчёт — `reports/generated/ml-port/<версия>/report.html`. Слепые итоги 2026 открываются только отдельным `--blind-check` после фиксации модели. Разности не подменяют годовой направленный ряд линии. `ml.line_experiment` требует первичного HTML для расширения годовой истории и сохраняет самостоятельную годовую модель.

После создания или получения проверенного артефакта функции для Fullstack доступны через `from ml import forecast, forecast_port`: `forecast(direction="inbound", end_year=2030)` и `forecast_port(end_period="2026-12")`. Для обратного направления линии — `outbound`; у каботажа `direction: null`. Без артефактов эти вызовы отклоняются. Годовой результат доступен через HTTP `/forecasts`; интеграция следует [контракту API](docs/api_contract.md). Полная инструкция, протокол, выходы и проверки: [ML README](ml/README.md).

Интерактивный отчёт о влиянии параметров: `python -m ml.sensitivity`. Для него нужен уже сохранённый годовой артефакт; переобучение не требуется. Команда напечатает путь к автономному `report.html`: откройте его браузером. Выбор направления/года и три регулятора показывают изменение дефицита и запаса провозной возможности. Нагрузка, исходная возможность и её прибавка — сценарные допущения в процентах от базового прогноза; это не измеренная мощность или обученное влияние факторов. Расчёты, сравнение примеров и CSV/JSON сохраняются отдельно в `reports/generated/sensitivity/`.

### Фиксация месячных моделей и проверка переноса

Перед первым запуском зафиксируйте код и конфигурацию в Git, пересоберите комплект
после изменения файлов его отпечатка и выполните `pipeline.verify` и тесты.
В происхождении модели сохраняются коммит и состояние отслеживаемого кода.

```bash
python -m ml.port_run --all-targets
```

Сначала проверьте выбранный метод, MAE/WAPE относительно naive и пропуски срезов
в `metrics.json` и `backtest.csv` каждого запуска. После фиксации выбора:

```bash
python -m ml.port_run --all-targets --blind-check
```

Эта команда открывает только два нужных выпуска 2026 и создаёт блокировку на
каждую цель. Для новых портов читаются зарегистрированные оригиналы SeaNews,
которые не дополняют обучение. Повтор с тем же состоянием читает сохранённый
результат; незавершённая проверка требует разбора. После просмотра методов и окон
не менять. Сентябрь ранее сверялся: полной независимости проверки не заявляем.
Результаты, ряды и модели остаются локальными.

`python -m ml.hypotheses` пересчитывает исследовательские оценки действий.
Для полной таблицы `action_scenarios.csv` нужен сохранённый **годовой** артефакт
линии `models/latest.json`. Если его нет, после проверки комплекта выполните:

```bash
python -m ml.run --end-year 2030
python -m ml.hypotheses
```

Календарь отделяет факт ремонта «Амбала» от планового возврата «Балтийска».
Резерв рассчитывается отдельно по годам календаря; без календаря эффект пустой.
Предел ж/д части применяется только к оценённой массе груза в вагонах.
Месячные модели и слепая проверка при этом не запускаются.
Основные действия для линии: А — резервный паром на время ремонтов, Б — сокращение портовой части оборота.
Дальневосточные порты проверяют перенос процедуры; параметры CAPEX/OPEX остаются открытыми.

побайтного совпадения блока C; повторные строки фактами не добавляются.
Текст расписания нужно сохранить из сообщения пользователя или взять из локальных
оригиналов дополнения: он исключён из Git вместе с остальными данными.

Регистрация выполняется без сети и новых зависимостей. Оригиналы сохраняются
в `data/raw/research_package/`, паспорта, таблицы и отчёт — в версионированном
каталоге `data/processed/research_package/`; текущая версия указана в `latest.json`.
Существующие реестр, манифест сборки и ML-входы не меняются. Поля и правила
описаны в [контракте](docs/contracts.md#регистрация-пакета-for-misha-12112026),
результат регистрации и недостающие материалы — в
[инструкции передачи](docs/for-misha-registration.md).

## Структура

| Каталог | Назначение |
|---|---|
| `docs/` | Договорённости, контракты и инструкции подготовки данных |
| `data/raw/` | Неизменённые первоисточники, локально |
| `data/interim/` | Промежуточные преобразования, локально |
| `data/processed/` | Проверенные таблицы для модели, локально |
| `data/examples/` | Малые примеры схем без вымышленных целевых фактов |
| `pipeline/` | Проверка и последующая сборка наборов |
| `ml/` | Код годового прогноза линии, месячного каботажа и временной проверки; инструкции в `ml/README.md` |
| `backend/app.py` | Создание приложения, API, CORS и регистрация единого React-интерфейса |
| `backend/frontend.py` | Раздача React-сборки, проверка актуальности и SPA fallback |
| `backend/api/v1/` | HTTP-маршруты и существующий расчёт чувствительности |
| `backend/schemas/` | Типизированные запросы и ответы |
| `backend/core/` | Настройки и ошибки |
| `backend/scenarios.py` | Общая арифметика баланса для API и отчёта чувствительности |
| `backend/tests/` | Контрактные HTTP-проверки |
| `frontend/` | Единственный основной React-интерфейс: Vite, production-сборка, встроенный калькулятор, прогноз и AI-панель |

Исходный `main.py` оставлен без изменений. Материалы кейса находятся в отдельной папке `кейс чемпионат/outputs`; их нужно подключать через реестр источников, а не переносить все файлы в Git.

Предложения к обсуждению цели, проверки прогноза и логистической цепочки: [вопросы команды](docs/team-discussion.md).

## Следующие решения команды

1. Выбрать проверяемый целевой ряд и его частоту; подтвердить, можно ли получить месячные тонны по нужной паре регионов.
2. Утвердить две гипотезы действий и подтверждённые диапазоны мощности, сроков, CAPEX/OPEX.
3. Выбрать модели и временные срезы проверки; решить охват логистической цепочки.
4. Зафиксировать обязательный объём интерфейса к сдаче и горизонт (2030 или гибкий до 2035).

Расширение покрытия данных, моделей и сценарных параметров требует предметной приёмки. Годовая модель линии уже подключена к API и React; признаки в `/config` и `/status` отражают доступность конкретных возможностей, а не готовность всех планируемых интеграций. Разработку каркаса и документации выполнил ИИ; человеку нужно проверить схемы, происхождение будущих чисел, запустить команды проверки и согласовать открытые решения перед сдачей.
