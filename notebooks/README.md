# Обзор данных в Jupyter

[dataset_overview.ipynb](dataset_overview.ipynb) — обзор всех CSV, включённых в манифест сборки, и реестра оригиналов. Внутри: инвентаризация, ссылки на источники, покрытие, пропуски, ключи, графики узкой паромной линии, справочных рядов, экспортных показателей и транзитной выборки, таблица пригодности для команды и место для заметок проверяющего. Ноутбук читает подготовленные таблицы, не переопределяя правила очистки из `pipeline/`.

В начале есть таблица происхождения всех 13 CSV. В каждом тематическом разделе указаны адрес первоисточника (если известен), путь к сохранённому оригиналу и путь к подготовленной таблице. Пути в пояснениях считаются от корня проекта; ссылки на оригиналы относятся к указанной версии комплекта. Для присланных файлов неизвестный сайт публикации не подменяется предположением. Ячейка `PREVIEW_DATASET` дополнительно выводит полные пути выбранного CSV и оригиналов, связанных с его `source_id`.

## Запуск

Нужны Python 3.11+ и локальные данные из рабочей папки либо архива передачи. Реальные CSV и оригиналы исключены из Git; после одного клонирования без передачи данных обзор не запустится. Из корня проекта:

```bash
python -m venv .venv
```

Активируйте окружение: Linux/macOS — `source .venv/bin/activate`, Windows PowerShell — `.\.venv\Scripts\Activate.ps1`. Затем:

```bash
python -m pip install -e ".[notebooks]"
python -m pipeline.build
python -m pipeline.verify
python -m jupyterlab notebooks/dataset_overview.ipynb
```

В Jupyter выберите Python из `.venv` и выполните **Run → Run All Cells**. В VS Code можно открыть `.ipynb` и выбрать `.venv` в меню ядра. Интернет нужен только для установки зависимостей; ячейки не скачивают источники. Корень проекта определяется из текущей папки и её родителей; запуск из `notebooks/` поддерживается.

Сначала выполняется `pipeline.verify`. Если код, реестр или исходники изменились, пересоберите комплект командой `python -m pipeline.build` в терминале. Повреждённый оригинал не исправляется пересборкой — нужен оригинал с ожидаемым хешем.

## Что можно менять

- `PREVIEW_DATASET` и `PREVIEW_ROWS` — таблица и размер примера для просмотра.
- `review_notes` — ваши выводы, вопросы, реально проверенные исходные ячейки, имя и дата проверки. Флаг человеческой приёмки по умолчанию выключен.
- `SAVE_REVIEW = True` в последнем блоке — сохранение сводных CSV, PNG, заметок и отчёта в `reports/generated/dataset_overview/<версия>/`. Повторный запуск обновляет файлы этого обзора; исходные таблицы остаются прежними.

Пустое значение не заменяется нулём; числовые поля преобразуются явно, коды стран и товаров остаются строками. Годовая история не превращается в месячную. Вложенные виды экспорта и разные объекты учёта не суммируются; распределение сроков транзита строится по декларациям, а не товарным позициям. Цель модели и гипотезы команды ноутбук не выбирает.

## Сохранить выполненный ноутбук и HTML

Из корня проекта с активной `.venv`:

```bash
python -m jupyter nbconvert --to notebook --execute notebooks/dataset_overview.ipynb --output dataset_overview.executed --output-dir reports/generated --ExecutePreprocessor.timeout=180
python -m jupyter nbconvert --to html reports/generated/dataset_overview.executed.ipynb --output dataset_overview --output-dir reports/generated
```

В Git сохраняется исходный ноутбук **без результатов ячеек**. Выполненный ноутбук, HTML, графики и сводки с реальными числами остаются в `reports/generated/`, исключённой из Git. Если работали в исходном `.ipynb`, перед коммитом очистите результаты:

```bash
python -m jupyter nbconvert --clear-output --inplace notebooks/dataset_overview.ipynb
```

Зависимости объявлены в `pyproject.toml`, группа `notebooks`. ИИ подготовил структуру обзора, код и пояснения. Выполнение ячеек проверяет расчёты на переданном комплекте; предметная сверка методики и исходных ячеек остаётся отдельной человеческой приёмкой. Открытые вопросы для команды находятся в последней таблице ноутбука; формат исходных таблиц и API не изменяется.
