# Прогнозный модуль: паромная линия, два направления

Экспериментальная демонстрация годовой массы перевозок **линии Усть-Луга — Калининград**, отдельно `inbound` (в область) и `outbound` (из области). Решение использовать существующий ряд и оба направления принято пользователем. Это девять годовых наблюдений 2015–2023 на направление. Человеческая приёмка методики источника остаётся открытой; весь грузовой коридор эта модель не описывает.

Код ML, сохранённый артефакт и подключённый API — отдельные состояния. **В текущей рабочей копии готовых артефактов моделей нет**; описанные ниже файлы создаются только при успешном запуске на подготовленных данных либо передаются отдельным проверяемым комплектом. Наличие исходников не подтверждает выполненное обучение или точность. Backend запускается без моделей; HTTP `/forecast` пока не зарегистрирован, `/api/v1/status` возвращает `components.ml: not_connected` и `capabilities.forecast: false`. Настройка адреса API основного интерфейса и отдельное размещение frontend описаны в [README](../README.md) и [контракте API](../docs/api_contract.md).

## Архитектура и связь с приложением

Экспериментальный `ml/` реализует годовой прогноз конкретной паромной линии в обоих направлениях. `ml.run` проверяет снимок данных, сравнивает три метода во временных срезах и сохраняет JSON-параметры, прогнозы и отчёт. Функция `forecast` из `ml` предоставляет Fullstack переносимый результат со статусом `forecast` и явными ограничениями; подключение HTTP/frontend выполняется отдельно. Региональные ряды, приблизительные месячные сводки и сценарная потребность автоматически в эту цель не попадают.

Отдельный `ml.port_run` использует `pipeline.model_inputs` для 36 месячных разностей портового каботажа со статусом `estimated`, не изменяя существующий ETL-комплект. Сравнительные колонки 2023 и основные годы 2024–2025 сохраняют роли, ячейки и оценку доступности по месяцу размещения URL. Временные срезы маскируют ещё не опубликованные значения; Ridge обучает лаг, среднее и календарные признаки только внутри окна. Доступ до целевого месяца проходит рекурсивно. Функция `forecast_port` из `ml` читает независимый JSON с сохранёнными интервалами из `models/port/`; направление и OD не назначаются. `ml.line_experiment` сравнивает длину годовой истории и раздельный/агрегатный подходы в отдельном отчёте, не заменяя существующую модель.

`ml.sensitivity` выпускает отдельный автономный HTML-отчёт по сохранённой годовой модели. Общая арифметика баланса нагрузки находится в `backend/scenarios.py` и используется также сценарным API. Python готовит сетку сочетаний пользовательских допущений; `frontend/sensitivity_report.html` отображает готовые строки, график и карту дефицита без повторения расчётной логики. Проценты берутся от прогноза как от масштаба демонстрации. Статусы, входные допущения, версии и границы направленного годового охвата сохраняются. Прогноз не переобучается, сценарии не включаются в факты/backtest.

## Запуск

На Linux/macOS из корня проекта сначала создайте окружение и активируйте его (нужен Python 3.11+):

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Если `.venv` уже создано, достаточно `source .venv/bin/activate`. Активация нужна в каждом новом терминале; после неё доступна команда `python`. На Windows PowerShell активация: `.\.venv\Scripts\Activate.ps1`.

Затем:

```bash
python -m pip install -e ".[ml]"
python -m pipeline.verify
python -m ml.run --end-year 2030
```

Без активации на Linux/macOS можно запускать напрямую: `.venv/bin/python -m ml.run --end-year 2030`. Готовый `report.html` лежит в папке отчёта, путь к которой команда напечатает в конце; откройте его браузером, чтобы увидеть графики и таблицы.

После установки зависимостей запуск работает офлайн. Нужен локальный комплект данных с заполненным `candidate_observations.csv` и соответствующим манифестом. После одного клонирования без оригиналов/CSV обучение не запустится; используйте архив передачи. Конвейер проверяет хеши и исходники только в пределах входов манифеста, включая частичные комплекты. Изменённый, пустой, дублированный, месячный или неподходящий по OD ряд отклоняется.

## Методы и проверка

Полный протокол: [`docs/ml-evaluation-protocol.md`](../docs/ml-evaluation-protocol.md). Запуск на архиве передачи: [`docs/ml-run-guide.md`](../docs/ml-run-guide.md).

- `naive`: последнее наблюдённое значение, обязательный baseline.
- `drift`: последнее значение плюс среднее годовое изменение.
- `ses`: ETS(A,N,N), простое экспоненциальное сглаживание без тренда/сезонности. Начальный уровень фиксирован первым наблюдением; единственный параметр сглаживания оценивается внутри обучающего окна. Тонны масштабируются перед оптимизацией для устойчивости; выходы снова в тоннах.

Предварительные срезы: 2015–2019 → 2020; 2015–2020 → 2021. Выбор для каждого направления по средней MAE этих двух проверок; при равенстве приоритет `naive,drift,ses`. Метод с ошибкой на одном предварительном срезе не участвует в выборе. Отдельный holdout: 2015–2021 → 2022; 2015–2022 → 2023. Выбор после теста не меняется, даже если другой метод оказался лучше на 2022–2023. Выбранный метод затем обучается на всей истории 2015–2023.

MAE — средняя абсолютная ошибка в тоннах. WAPE — сумма абсолютных ошибок / сумма фактов × 100%; при нулевом знаменателе значение не определено (`null`). Для неполного набора проверок метрика не публикуется вместо сравнения на разных периодах. Полный backtest при успешном запуске содержит 24 проверочных прогноза: два направления × три метода × четыре года. Это не 24 независимых периода одного ряда.

Горизонт backtest — один год. По два holdout-наблюдения на направление не подтверждают устойчивость модели или точность до 2030. `2024–2026` остаются прогнозом: последний факт — 2023, даже если текущий календарный год позднее. Нельзя добавлять прогнозы в историю как наблюдения.

## Выходы и сохранение

`models/latest.json` указывает на успешный `models/<model_version>/model.json` с SHA-256. JSON содержит параметры, обучающие значения, происхождение и версии библиотек, данных, кода и конфигурации. Pickle не используется. Обе модели обслуживаются без повторной подгонки и без statsmodels; для обучения нужна группа `ml`. Повторный запуск одинаковых входов/окружения сохраняет версию и время создания, а значения воспроизводятся. `generated_at` в ответе — время создания прогнозного артефакта.

В `reports/generated/ml/<model_version>/`:

- `report.html`, `inbound.png`, `outbound.png` — локальный обзор, факты, прогнозы, модельные интервалы и временные проверки;
- `forecast.csv`, `forecast.json` — прогнозы 2024–2030 обоих направлений с версиями и предупреждениями;
- `backtest.csv`, `metrics.json` — все ошибки с версиями, метрики, выбор и holdout отдельно, сравнение с baseline;
- `model-card.md` — паспорт, покрытие, качество относительно baseline, разбор 2022–2023, что нельзя публиковать, участие ИИ и состояние человеческой проверки;
- `break_2022_2023.csv`, `external_terminal_check.csv` — ошибки в годы перелома и внешняя сверка со строкой терминала, не участвующая в выборе;
- `run_manifest.json` — хеши выходов, версия модели и воспроизводимые входы.

Нормальные интервалы 80%/95% используют модельную дисперсию; её формулы и оценка описаны в карточке. Границы/точечные значения ограничиваются нулём с предупреждением. Эти интервалы условные, не калиброваны на независимой большой выборке и не учитывают неизвестные структурные изменения. При нулевой оценённой дисперсии предупреждение сохраняется.

Все модели, реальные выгрузки и отчёты остаются локально, вне Git. Передавать нужно и код, и комплект данных/моделей, проверяя SHA-256.

## Функция для Fullstack

```python
from ml import forecast

result = forecast(direction="inbound", end_year=2030)
reverse = forecast(direction="outbound", end_year=2030)
```

Результат содержит статус `forecast`, единицу, период, модельные интервалы, точку прогноза, версии, происхождение и предупреждения. Конечный год — 2024–2030. Функция не меняет модель и не заполняет пропуски фактической истории. Ошибочное направление, повреждённый/отсутствующий артефакт и неподдерживаемый год отклоняются с русским сообщением. Контракт v0.7: `docs/contracts.md`. Пример полного ответа — `forecast.json`.

Этот этап предоставляет ML-функцию. HTTP API и интерфейс подключаются Fullstack отдельно. Прогноз перевезённой массы не назначается автоматически сценарием спроса, приростом мощности или экономическим эффектом.

## Интерактивный отчёт чувствительности

С активной `.venv` и сохранённой моделью:

```bash
python -m ml.sensitivity
```

Откройте напечатанный `report.html` браузером: он работает офлайн без API и внешних библиотек JavaScript. Для просмотра через HTTP можно запустить `python -m http.server 8766 --bind 127.0.0.1 --directory reports/generated/sensitivity`, открыть `http://127.0.0.1:8766/` и выбрать папку версии → `report.html`.

Отчёт позволяет выбирать направление, год, нагрузку (60–180%), исходную провозную возможность (60–160%) и её увеличение (0–60%); шаг — 10 процентных пунктов. Все три процента берутся от точечного базового прогноза выбранного года, а не друг от друга. Это введённые демонстрационные допущения. Рядом показаны тонны за год, исходный/остаточный дефицит, его сокращение, запас возможности, график чувствительности к нагрузке и карта сочетаний параметров. Прогноз и его интервалы от регуляторов не меняются. Выбранный расчёт можно скачать в JSON, весь набор — в CSV/JSON; печать браузера позволяет сохранить PDF.

Все численные балансы готовятся в Python через `backend.scenarios.capacity_balance`, общий с существующим API. JavaScript выбирает рассчитанные сочетания и рисует графики. Полный горизонт 2024–2030 даёт 14 014 сочетаний; короткий горизонт — меньше. Команда не переобучает модель и не изменяет её исходный отчёт или манифест. Собственный манифест отчёта фиксирует хеши, версии модели/данных и `human_methodology_review: pending`.

Число паромов, тарифы, сроки доставки и затраты в этот расчёт не входят: для них нет принятой методики и подтверждённых параметров. Направления показаны отдельно; распределение общего флота и терминальной мощности между ними не проверяется. Два действия для команды этим отчётом не утверждаются.

## Две отдельные модели и годовой исследовательский отчёт

С активным окружением из корня проекта:

```bash
python -m pip install -e ".[ml]"
python -m pipeline.verify
python -m ml.port_run
python -m ml.line_experiment
```

`ml.port_run` готовит 36 месяцев общего каботажа порта Калининград (2023–2025). Двенадцать месяцев 2023 восстанавливаются из сравнительных колонок публикаций 2024, 2024–2025 — из основного года. Все месяцы имеют статус `estimated`; ячейки, формулы, роли и источники сохранены в `training_series.csv`. Пропуски/отрицательные разности/дубли останавливают подготовку. Это портовая перевалка без OD и направлений, не прогноз Усть-Луги или всего коридора.

Модели: последнее значение, соответствующий месяц прошлого года и Ridge с `alpha=0.1,1,10`. Ridge реализована на NumPy: свободный intercept, L2-штраф коэффициентов, стандартизация X внутри обучающего окна. Признаки — `lag_1`, среднее трёх предыдущих месяцев, синус/косинус календарного месяца. В дальнейших шагах используются рекурсивные прогнозы. Коэффициенты всех регрессий показаны в отчёте, даже если выбран baseline. Экономические индексы сохранены в `factor_candidates.csv` с неподтверждённой датой доступности, в модель не включены.

Выбор — MAE одномесячных выдач января–июня 2025. Проверка — июль–декабрь; выбор после неё не меняется. Горизонт 3 оценивается двумя непересекающимися блоками на каждом этапе. MAE/WAPE относятся к восстановленному ряду. Срезы учитывают публикацию: официальные URL содержат месяц размещения, `available_by` консервативно равен его последнему дню. Декабрь 2024 доступен только в январе 2025, поэтому январский срез не использует его. Неизвестные значения маскируются, окна признаков пропускаются, до цели строятся промежуточные прогнозы. `model_steps` может быть больше календарного горизонта. Точный день публикации неизвестен — ограничение отражено в паспорте.

Итоговое обучение — все 36 месяцев; прогнозная точка декабрь 2025. Полный набор доступен к концу января 2026: январская оценка помечена `timing: nowcast`, последующие — `forecast`. По умолчанию выводятся 12 месяцев 2026; можно задать `python -m ml.port_run --end-period 2030-12`. После первых 12 месяцев это экспериментальная экстраполяция. Интервалы 80/95% — 2000 рекурсивных симуляций центрированных ошибок обучения, seed 42, фиксированные коэффициенты, граница ноль. Фактическое покрытие и неопределённость параметров не подтверждены.

```python
from ml import forecast, forecast_port

line = forecast(direction="inbound", end_year=2030)
port = forecast_port(end_period="2026-12")
```

Функция каботажа читает отдельный JSON с уже рассчитанными интервалами и не переобучается; для обслуживания не нужен NumPy. Ответ включает `target_id`, охват порта, `direction: null`, статус цели `estimated`, версии, модель, месяцы, интервалы, дату доступности и предупреждения. Указатель находится в `models/port/latest.json`, отчёт — в `reports/generated/ml-port/<версия>/report.html`. Существующий годовой указатель `models/latest.json` сохраняется.

`ml.line_experiment` сохраняет отдельное исследование в `reports/generated/ml-line-research/<версия>/`: история с 2015 против истории с 2011, те же 2020–2021 для выбора и 2022–2023 для проверки. Дополнительные восемь направленных строк 2011–2014 читаются из проверенного оригинала. В исследовании также сравниваются независимые прогнозы направлений с прогнозом суммы и распределением по суммарным историческим долям только обучающих лет. Метод агрегата выбирается совместно по направлениям на development; holdout не меняет решение. Исторические даты годовых публикаций неизвестны, поэтому это ретроспективная проверка по периодам. Исходная годовая модель и её прогноз с интервалами сохраняются.

Годовой отчёт рассматривает две исходные гипотезы DOCX: раздельное планирование с резервированием и совместные встречные партии. Очередь, свободная вместимость и экономия без заявок/рейсов/расходов не оцениваются.

Оба отчёта автономны: откройте `report.html` браузером. Для HTTP-просмотра: `python -m http.server 8767 --bind 127.0.0.1 --directory reports/generated`; затем выберите папку `ml-port` или `ml-line-research` и версию. У каждого комплекта есть CSV/JSON, паспорт и манифест SHA-256. Повторный запуск одинаковых входов сохраняет версии, время и байты.

## Проверки новых экспериментов

Для общего набора тестов из корня проекта установите `python -m pip install -e ".[dev,data,ml]"`, затем выполните `python -m pytest -q`. Группы `dev` достаточно только для отдельных HTTP-проверок `python -m pytest backend/tests -q`; общий сбор тестов также импортирует NumPy из группы `ml`. Команды ниже описывают проверки из `tests/`, без HTTP-тестов `backend/tests/`.

`python -m unittest discover -s tests -v` проверяет месячные разности и январь, роли публикаций, дубли/пропуски, доступность на дату выдачи, отсутствие будущих данных в признаках и выборе, рекурсивные горизонты, интервалы, сохранение/загрузку, воспроизводимость и сохранение годовой модели. Тестовые примеры синтетические; реальные метрики появляются в отчётах только после запуска на проверенных реальных данных.

## Проверки годового прогноза и участие ИИ

`python -m unittest discover -s tests -v`: проверка прошлого в каждом срезе, независимость выбора от будущих фактов, ошибки/нулевой знаменатель, фильтры цели, аналитические интервалы, сравнение SES с библиотекой, сохранение/загрузка и повреждение модели. Тестовые данные синтетические и не входят в оценку точности реального ряда.

ИИ подготовил код, автоматические проверки и отчёт. Человек должен проверить определение массы/охват источника и обсудить пригодность выбранного алгоритма. Никакая автоматическая проверка не отмечается как человеческая приёмка.
